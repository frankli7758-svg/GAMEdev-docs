## 2. 四条硬约束（资产准入标准）

任何资产必须**四条全过**才能进入工程，一条不过就换，不在工程里改。

| # | 约束 | 判定方法 | 不合格特征 |
|---|---|---|---|
| 1 | **尺寸 = 真实人体** | 场景里与 1×1×1 Cube 并排，角色高度 ≈ 1.8 倍 | 明显更大/更小（如 3.27 米） |
| 2 | **骨架 = Humanoid** | Inspector → Rig 页 → Animation Type = Humanoid，**无红色警告** | Generic；或 Humanoid 但提示 Rig Configuration mis-match |
| 3 | **动画覆盖必需状态** | 资产页动画清单里能数出：idle / walk / strafe(左右后) / run / aim / fire / reload | 做到一半发现缺 aim 或 strafe |
| 4 | **枪的 pivot 在握把、+Z = 枪口** | 拖进空场景，看轴线与网格的关系 | 旋转时绕枪管中段转、枪口朝 −Z 或 +X |

**第 3 条必须在付费之前确认**，看资产页的 "List of Animations"，不要下载后才发现缺项。

### 3.2 关于 Rifle Animset Pro "不兼容 URP"

**结论：可以用，那个标签是误导。**

资产页确实标着 `URP: Not compatible`，但同一页的 "Additional compatibility information" 原文写着：

> The pack's main content is .fbx animations. **They will work with any rendering pipeline and even outside of Unity.**

原因：

- Asset Store 的管线兼容标签是给**含材质/Shader**的资产用的
- 纯动画 `.fbx` **不包含任何材质**，只存骨骼关键帧，与渲染管线无关（甚至能在 Unity 之外用）
- 标成 "Not compatible" 是因为包里**附带**了演示角色/演示场景/PlayMaker 控制器，那部分用的是 Built-in Standard shader。URP 下它们会变粉——**但那只是演示内容，不是你用的东西**

**绕开的做法**：导入时**只勾动画 `.fbx`**，跳过以下内容：

- `Demo` / `Scenes` / `Examples`（演示场景）
- `Materials` / `Textures`（演示角色的材质）
- `PlayMaker`（需要单独买 PlayMaker 插件，本项目不用）
- `InputManager_Replace`（会覆盖你的输入配置，**绝对不要导**）

跳过之后，包里只剩纯动画数据，URP 完全无感。

### 3.4 推荐

**选方案 B（预算允许的话）。**

理由：

1. **AimOffset 是 TPP 射击的核心机制**，Mixamo 给不了。它能让你在"身体朝前跑"的同时，上半身和枪口转向侧后方瞄准——COD 的瞄准手感就建立在这上面
2. 动画是**专为第三人称步枪射击设计**的（88 个动捕，含蹲/趴/受击/死亡/投雷/近战），不是通用动作库拼凑
3. $50 换 88 个动捕，单价不到 0.6 美元

**但预算为零时方案 A 完全能跑起来**（见 §13），只是瞄准只能"整体转身"，做不到"上半身独立瞄准"。

**但有一个风险必须提前验证**：Kubold 动画是 HumanIK 骨架，Mixamo 模型是 mixamorig 骨架。两者都是 Humanoid，**基础动画重定向没问题**，但 **Additive 瞄准动画对模型比例敏感**，跨模型可能出现姿势偏移。

→ **阶段 1 必须实测**：拿一个 Mixamo 模型 + 一个 Rifle_Idle + 一个 AimAdditive，确认姿势正常。不正常就退回方案 A 或改用非 Additive 的 aim。

## 6. 已知技术坑（2026-10-26 教训，务必先读）

### 6.1 编辑器里 SkinnedMeshRenderer 的 bounds 不可信
`sharedMesh.bounds` + transform 换算是错的（蒙皮顶点由骨骼决定，renderer 的 transform 不参与）；`Renderer.bounds` 在编辑器里是**旧缓存**，模型移动后不更新，会导致每次算出的偏移相同、反复叠加把模型推到天上。

**→ 量尺寸只信两样：骨骼 `Transform.position`，或者肉眼对比 Cube。**

### 6.2 "所有骨骼里最低的那个"不是脚底
`B-root` / `Armature` 这类根骨骼常躺在脚下方 1 米多，用它会得出"已贴地"的假象。

**→ 找脚必须走 Avatar 人形映射的 `ToeBase` / `Foot`，或排除名字含 root/armature/proxy 的节点。**

### 6.3 骨骼命名大小写敏感
`t.name.Contains("Head")` 匹配不到 `B-head`。跨资产找骨骼一律走 Avatar 的 `humanName → boneName` 映射。

### 6.4 跨骨架不能用 Copy From Other Avatar
Mixamo 的 `mixamorig:Hips` 和 Kevin 的 `B-hips` 不是一套，复制会报 `Transform 'B-hips' not found`，Avatar 无效、clip 都生成不出来。

**→ 同骨架才能 Copy；跨骨架用 Create From This Model，让每个动画自己生成 Avatar（Humanoid 的重定向发生在播放时）。**

### 6.5 `muzzle` 有值就完全接管射线
`WeaponController.ComputeRay` 里，只要 `muzzle` 非空，射线起点和方向**全由它决定**。枪挂在手上会随摆臂抖动，射线跟着抖 → "瞄着打不中"，且极难排查。

**→ 枪只做视觉，`muzzle` 留空，判定走 `chestHeight + transform.forward`。**

### 6.6 Play 模式的修改必然还原
Unity 的机制，不是 bug。要保留必须记录数值（`Copy Component` / `Paste Component Values`，或写工具存 `EditorPrefs`）。

### 6.7 Inspector 里 Position 和 Scale 挨着，容易拖串
改 Position 用**输入框点数字**，不要在字段上左右拖。改完扫一眼 Scale 还是不是 1。

### 6.8 整体缩放不改变"人 : 枪"比例
模型缩到 1.82 米，枪也跟着缩 0.557 倍，看起来还是一样小。**两件事要分开做**：修模型尺寸 + 单独调枪尺寸。

## 10. 音效资源

### 10.1 COD 打击感是怎么做出来的（关键，先看这个再挑素材）

COD 的枪声不是"一个 wav 文件"，而是**多层叠加 + 随机化 + 距离分级**。直接找"一个听起来像 COD 的枪声"是找不到的，得按结构去拼。

#### 枪声的三层结构

| 层 | 频段 | 作用 | 缺了会怎样 |
|---|---|---|---|
| **Punch / Thump**（低频冲击） | 0~100 Hz | "重量感"、"后坐力" | 声音变薄、像玩具枪 |
| **Crack**（中频爆裂） | 500 Hz~3 kHz | "锐利度"、"威力" | 声音发闷、糊 |
| **Tail**（尾音/环境反射） | 全频段衰减 | "空间感" | 像在真空里开枪，没有场景 |

**COD 的枪声低频特别足**，这是它听起来"沉"的核心原因。俯视角游戏尤其需要低频，因为相机远、其他声音少，低频是唯一能传递"力量"的东西。

#### 近距 / 远距双版本

专业做法是每个武器做**两个版本**：
- **近距**：细节丰富、高频完整、有机械声
- **远距**：低频突出、高频衰减、有长尾音

按玩家与声源的距离交叉淡化。这是"真实感"的真正来源，也是业余和专业的差距所在。

对单机项目可以简化：**一个版本 + 距离衰减曲线 + 混响区**，效果能到 80%。

#### 命中反馈分层（这条决定"打中了爽不爽"）

| 材质 | 声音特征 | 备注 |
|---|---|---|
| **血肉**（僵尸） | 闷响 + 湿润黏腻 + 骨碎 | 低频偏多，短促 |
| **爆头** | 单独一版，更闷更重 + 特殊的"顿" | **必须有独立音源**，这是爽点的核心 |
| **金属** | 清脆 + 金属余响（ping） | 打铁皮、油桶 |
| **混凝土** | 碎屑 + 粉尘感 | 打墙、地面 |
| **木/玻璃** | 各自独立 | 打击感层次 |

#### 机械声（最容易忽略、最能加质感）

一把枪远不止"开火"一个声音：

- **换弹拆成 4~6 段**：退弹匣 → 弹匣落地 → 插弹匣 → 拍实 → 拉枪机 → 完成
- **空仓击发**：金属干响（dry fire）
- **弹壳落地**：每种口径不同
- **枪机往复**：连发时每发一次的机械声

**这些声音要和动画时间点对齐**，不是靠一个"换弹音效"糊过去。这是"手感有细节"的关键。

## 11. 音效实现流程

### 11.1 Unity 侧需要建的东西

```
AudioMixer
├── Master
│   ├── SFX
│   │   ├── Weapon      ← 开火、机械
│   │   ├── Impact      ← 命中
│   │   ├── Footstep
│   │   └── Enemy
│   ├── Ambience        ← 环境
│   └── UI
```

设置页的音量滑块接到 `Master / SFX / Ambience / UI` 四条总线上——现在设置页那几个灰掉的选项就能真正生效了。

### 11.2 枪声随机化（避免"电子枪"感）

同一个 wav 连打 30 发会听出机械感。必须加随机：

- **音高随机**：`pitch = 1.0 ± 0.05`（±5%）
- **音量随机**：`volume = 1.0 ± 0.08`
- **多版本轮播**：每把枪准备 **3~5 个变体**，随机选（不重复上一发）
- **轻微起始时间偏移**：几毫秒，避免绝对同步

### 11.3 导入设置

| 项 | 值 | 理由 |
|---|---|---|
| Load Type | **Decompress On Load**（短音效） | 枪声、命中都是短音，预解码省 CPU |
| 长音频（环境） | Streaming | 省内存 |
| Compression Format | **Vorbis**（移动/WebGL）或 **PCM**（PC 短音效） | PC 上短音效用 PCM 质量最好 |
| Force To Mono | 枪声/命中 **勾选** | 3D 音效由 AudioSource 定位，双声道没意义还费一倍内存 |
| Sample Rate | 保持原样（44.1k / 48k） | 不要重采样，会损失高频 |

### 11.4 触发点

| 音效 | 触发位置 |
|---|---|
| 开火 | `WeaponController` 开火成功的那一帧（已有统一入口） |
| 空仓 | `DryFireAttempted` 事件（代码里已经有这个 event） |
| 换弹分段 | 按动画时间点，用 `AnimationEvent` 或协程定时 |
| 命中 | 射线命中的材质（Layer 或 Tag 判定）+ 命中点位置 |
| 弹壳 | 开火后 0.1~0.2 秒 |

## 15. COD 枪声是怎么"做"出来的

你说得对，而且这是整个音效环节最重要的一条认知：

> **COD 的枪声不是录音室实录，是"实录 + 大量后期"的合成品。直接播实录素材，只会又刺耳又糊。**

原因很简单：真实枪声的**动态范围**是 140 dB 以上，瞬态极短，低频能量巨大。人耳在游戏里连续听 30 发，实录会：

- 高频刺耳（尤其戴耳机）
- 低频糊成一坨，听不清节奏
- 每一发都一样，没有层次

所以专业做法是**把实录"拆开"，按频段重新组装**，让它"听起来像枪"而不是"听起来像录音"。

### 15.1 实录 → 游戏化的六步加工

| 步 | 做什么 | 为什么 | 工具 |
|---|---|---|---|
| 1 | **降刺耳**：8~12 kHz 以上做低通 / 衰减 3~6 dB | 去掉"嘶"和耳膜刺痛 | EQ |
| 2 | **切浑浊**：200~400 Hz 衰减 2~4 dB | 这一段是"糊"的元凶，实录里能量过多 | EQ |
| 3 | **提 crack**：1~3 kHz 提升 3~5 dB | 这是"枪感"的核心，让人听出"脆" | EQ |
| 4 | **补低频**：40~80 Hz 加一段正弦或实录低通，短衰减（80~150 ms） | 实录的低频被压过之后会"瘦"，这层补回"重量" | 合成 / 低通采样 |
| 5 | **饱和/失真**：轻度 tube / tape saturation | 让声音变"厚"、"有攻击性"，**这是 COD 味的关键** | 失真插件 |
| 6 | **瞬态塑形 + 限幅**：加强 attack，压住尾巴，限幅防削波 | "砰"更干脆，整体响度更均匀 | Transient Shaper + Limiter |

**关键洞察：第 4 步和第 5 步是"游戏化"的分水岭。** 只做 EQ（1~3 步）会得到"干净但单薄"的枪声；补上低频层和饱和之后，才会有 COD 那种"沉、厚、有压迫感"的听感。

### 15.2 分层结构（一个枪声 = 4 个音轨叠起来）

```
第 1 层  Sub Thump    40~80 Hz 正弦，衰减 100ms      → "重量"、"后坐"
第 2 层  Body/Crack   实录主体，EQ 处理过            → "枪感"、"脆"
第 3 层  Mechanical    枪机、弹壳，实录高频          → "质感"、"真实"
第 4 层  Tail          混响尾巴，室内短、室外长      → "空间"、"场景感"
```

**在 Unity 里就是 4 个 AudioSource 同时播，或者预先在 DAW 里混成 1 个文件。**

对单机项目，建议**预先混好**（一个文件），性能和调参都简单；只有需要"远近分级"时才拆开做实时混合。

### 15.3 在 Sonniss 里怎么搜"已经处理过的"

你觉得 Sonniss 素材"太写实"，是因为搜的方向不对。同一个库里，**素材是分两类的**：

| 类型 | 特征 | 搜这些词 |
|---|---|---|
| **Raw / Source**（实录原素材） | 未处理、动态大、刺耳 | `source`、`raw`、`field recording`、`recording` |
| **Designed**（已设计过的） | 已压缩、已 EQ、可直接用 | **`designed`**、`sound design`、`cinematic`、`hollywood`、`trailer`、`layered` |

**搜 `designed` 或 `cinematic` 是关键。** Sonniss 的包里，凡是名字带这两个词的文件，都是供应商处理过的成品，离"游戏可用"更近。

具体建议：

1. 下载后在文件浏览器里搜文件名含 `designed` / `cinematic` / `trailer` 的
2. 优先看 **Boom Library** 的贡献包——他们的 `Cinematic Guns` 系列本身就是为影视/游戏设计的
3. **科幻枪声（sci-fi weapon）反而更接近游戏化听感**——它们 100% 是合成的，处理手法和游戏枪声同源。可以做参考素材、也可以直接当"未来武器"

| 工具 | 价格 | 说明 |

| **Reaper** | $60（个人授权） | **游戏音效行业的实际标准**。轻量、快、批处理强，做游戏音效性价比最高 |

### 15.5 一个可以直接照做的配方

拿一个 Sonniss 的 `designed` 枪声，按这个顺序处理：

```
1. 低通 12 kHz（斜率 12 dB/oct）
2. EQ：-3 dB @ 300 Hz，+4 dB @ 2 kHz
3. 复制一轨，低通 80 Hz，音量 -6 dB，加 120 ms 衰减包络  → Sub 层
4. 主轨加轻度饱和（drive 15~25%）
5. 瞬态塑形：attack +30%
6. 整体限幅，输出峰值 -1 dBFS
7. 导出 44.1 kHz / 16 bit WAV
```

**在 Unity 里再叠一次随机化**（音高 ±5%、音量 ±8%、3~5 个变体轮播），就基本能听出"游戏枪声"的味道了。

### 15.6 换弹声同理

换弹不是"一个换弹音效"，是**4~6 段独立音效按动画时间点触发**：

- 弹匣卡榫释放（金属咔哒）
- 弹匣滑出 + 落地（塑料 + 金属）
- 新弹匣插入（闷响 + 卡到位）
- 拍实弹匣（手掌拍击）
- 拉枪机（金属往复 + 复位）

**每一段单独处理、单独随机化**，这是"细节感"的来源。用同一个文件拉长/缩短是做不出来的。
