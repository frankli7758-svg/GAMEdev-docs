# 物品图标（透明 PNG）接入规范

> 起因：用户复测 C-1 时报 **"我现在没法测试因为我根本看不清"** ——
> 灰盒阶段每个物品只画一个**显示名首字**浮在品质色块上（`海` / `太` / `显`…），
> 根本分辨不出是什么东西，也就无法判断"光晕有没有盖住物品"。
>
> 本文给出**贴图数值规格**和**接入方式**。代码侧已经支持（见 §代码），
> 你只要按规格出图、把图拖进物品资产的 `Icon` 字段即可，**不需要改任何代码**。

---

## 1. 代码是怎么用这张图的

```
ItemDefinitionAsset.icon  (Sprite，资产上的字段)
        ↓  按 Id 查
ItemDatabase.GetIcon(defId)
        ↓
InventoryUi.GetIcon(defId)
        ↓
ItemCellView.RefreshVisual()  →  Image.sprite + preserveAspect
```

三个要点：

| 要点 | 说明 |
|---|---|
| **图标不进 Core** | `Assets/Scripts/Core/` 是 100% 纯 C#（连 `using UnityEngine` 都没有）。`Sprite` 是 Unity 类型，塞进 `ItemDef` 会把规则层焊死在引擎上，将来"逻辑搬到服务器"（§3.1 预留）就做不了。所以 Core 只管 `Id`，图标是**表现层**的事 |
| **没配图自动兜底** | `icon == null` → 退回现在的"显示名首字"。**可以逐个慢慢补**，不会因为缺图变成空白 |
| **有图就藏掉首字** | 否则首字会压在图标上。数量文字仍显示在右下角 |

---

## 2. 贴图数值规格（这是你要的答案）

### 2.1 尺寸——按物品**占位**给，不要一律方形

界面里 1 格 = **48 px**（1920×1080 设计分辨率）。代码用 `preserveAspect`（等比缩放 + 居中），
所以**贴图宽高比 ≈ 物品占位宽高比**时利用率最高。

| 物品占位 | 格位像素（1080p） | **建议贴图尺寸** | 备注 |
|---|---|---|---|
| 1×1 | 48 × 48 | **128 × 128** | 2.6× 余量，够清晰 |
| 2×1 / 1×2 | 96 × 48 | **256 × 128** | 与占位同宽高比 |
| 2×2 | 96 × 96 | **256 × 256** | 海水过滤器就是这一档 |
| 1×4 | 48 × 192 | **128 × 512** | 长条；不要出方图 |
| 2×4 | 96 × 192 | **256 × 512** | 太阳能板 |

> **如果嫌按尺寸出图麻烦**：统一出 **512×512** 也能用，但长条物品（1×4 / 2×4）
> 等比缩放后只用到中间一条，实际显示宽度会被压到 42 px 左右 —— 看着会比同尺寸的方图小一圈。
> **推荐做法**：1×1 / 2×2 用 256×256；长条用 128×512 或 256×512。

### 2.2 其他硬要求

| 项 | 要求 | 为什么 |
|---|---|---|
| 格式 | **PNG，RGBA** | 需要 alpha 通道 |
| 背景 | **真透明**（不能是白底/黑底） | 格子底色是"品质色"（白/绿/蓝/紫/金/红），要透出来。带底色的图会把品质色盖掉 |
| 留白 | 四周留 **5%~8%** 透明边 | 图标顶到格子边会显得挤，且和光晕贴在一起看不清 |
| 不要画品质 | **别把品质底色/边框画进 PNG** | 品质色由代码画（`ItemQualityPalette`），画进图里就重复了，改品质还得重出图 |
| 描边 | 建议带 1~2px 深色描边 | 红/金色底上的浅色图标没有描边会糊在一起 |
| 命名 | **与 `itemId` 一致**，如 `item_water_filter.png` | 方便以后写批量挂图脚本 |
| 路径 | `Assets/Art/Items/` | 和其它美术资源分开 |

### 2.3 Unity 导入设置（逐项，按这个勾）

选中 PNG → Inspector：

| 设置 | 值 | 说明 |
|---|---|---|
| Texture Type | **Sprite (2D and UI)** | 不改这个，Image 里选不到 |
| Sprite Mode | **Single** | |
| Mesh Type | **Full Rect** | `Tight` 会把半透明边缘裁掉，UI 里会出现图标被切一角 |
| Pixels Per Unit | 100（默认） | 对 UI 无影响 |
| Extrude Edges | 1 | |
| Wrap Mode | **Clamp** | `Repeat` 会让边缘出现拉丝 |
| Filter Mode | **Bilinear** | |
| **Compression** | **None** 或 **High Quality** | ⚠️ 默认的 `Normal Quality` 是 DXT，**透明边缘会出现脏色块**，小图标尤其明显 |
| **Generate Mip Maps** | **关** | UI 不缩放，开了只会糊 |
| **Alpha Is Transparency** | **✔ 勾上** | 不勾透明区边缘会出现黑边 |
| sRGB (Color Texture) | ✔ 勾上 | |
| **Max Size** | **≥ 512**（长条物品 ≥ 1024） | 小了会被强制缩放，128×512 的图会被压成 128×maxsize |

## 3. 怎么挂到物品上（不用改代码）

1. 把 PNG 放到 `Assets/Art/Items/`
2. 按 2.3 设好导入参数 → **Apply**
3. 选中 `Assets/Data/Items/item_water_filter.asset`
4. Inspector 里找到 **`Icon`** 字段，把 Sprite **拖进去**
5. 进 Play，打开那个"固定 3 个海水过滤器"的测试箱（见 §4）

> 物品资产**不会被脚本覆盖**：`StageCSetup.CreateItemAssets()` 只在资产**不存在**时写值，
> 已存在的资产一个字都不改。所以挂上去的图、调过的数值都能留住。

## 4. 配套的验证箱：`container_test_icon`

新增一只测试箱 **"测试箱（固定 3 个海水过滤器）"**：

| 参数 | 值 | 作用 |
|---|---|---|
| 网格 | 4×4（16 格） | 3 × 2×2 = 12 格，放得下 |
| `rollMin` / `rollMax` | **3 / 3** | 一定抽 3 次 |
| `forcedQualities` | **[Exotic]** | 3 次都锁定红品质，绕开等级概率表 |
| 战利品池 | **只有** `item_water_filter` | 每次抽取的唯一候选 |
| 物品堆叠上限 | 1 | 3 次各出 1 件 → **3 个独立堆叠** |

结果**恒定**为"3 个海水过滤器"，**不依赖随机种子**—— 纯配置实现，没有为它写任何特殊代码。

场景里位置：`(7, 0.5, -8)`（`LootCrate_04_TestIcon`，`instanceKey = crate_test_icon`），
放在金红测试箱的 -Z 方向 4 米，避免两只箱子的 3 米交互范围重叠。

## 5. 为什么"随便出一张图"也能用（但不好）

`preserveAspect = true` 意味着**任何宽高比的图都能显示**，只是：

- 图比格子宽 → 上下留空多，图标变小
- 图比格子窄 → 左右留空多，图标变小
- 所以"能看"和"清楚"是两件事。按 §2.1 的比例出图，图标利用率最高。
