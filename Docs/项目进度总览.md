### 3.6 2026-10-21：爽感、沉浸感与长期目标设想（💭，尚未排期）

> **定位**：本节是按系统归口的**未来设计备忘**，不是开发指令，也不是阶段 7 新增待办；优先尊重 §2 的真实状态与 §3.1~§3.3 现有排期。具体数值、配额、收费、演出时长、触发阈值均需未来原型验证。下述引用的角色、场景和呼号是示例或当前创意方向，不代表资产/代码已经存在。

#### 3.6.1 统一的体验设计原则（跨功能）

- **核心目标**：增强射击爽感、军事组织归属感、行动后果与成就感；优先考虑小投入、大回报的反馈改动。
- **双层情绪结构**：战局级「探索→遭遇→危机→反击→胜利/撤离」，事件级「铺垫→期待→玩家行动→高潮→结果确认→余韵」；可嵌套，但**不强迫每个事件都演满六步**。
- **玩家主动性**：高潮应主要由玩家的准备、操作或决策促成，不靠无缘由的强制过场；声音、UI、NPC 表演与真实世界结果形成一致因果链。
- **长期动机结构**：「先体验价值→玩家主动追问→通过人物/世界发现获取渠道→确立长期目标→努力获得自主使用权限」；仅用于适合的少数关键能力，避免处处套公式。
- **反馈密度与反差**：稀有高潮应与安静探索、风险和资源消耗形成对照；不要每次普通击杀都触发大片式演出。余韵允许保留战场痕迹、简短战果汇报，不剥夺玩家操作。
- **实现原则**：优先复用 `IDamageable`/`FactionRules`、`NoiseSystem`、`ToastHud`、`DamagePopup`、`RaidDirector`；Core 保持纯 C#，不要引入全局 `Time.timeScale = 0`；可先用灰盒、字幕和占位音效验证实际体验。

#### 3.6.2 枪械手感、击杀确认与战果分数（战斗 C、音频 G、HUD H）

- **高性价比微反馈优先**：枪口/命中/爆头/装甲/空仓/换弹的辨识性音效；射击反馈与敌人受击姿态一致；室内外声音空间差异后置。当前**零声音**，属于未来音频工作，不要误报已完成。
- **新增 Combat Score Feedback（💭）**：在准星侧或适合俯视角的避让位置显示普通击杀、爆头、打断攻击、多杀等反馈；技巧奖励分层，过密击杀显示合并/累积，避免与已实现 `DamagePopup`、`ToastHud` 抢屏。
- **真正的战斗事件才计分**：击杀、精英死亡、攻击机扫射等均使用实际伤害/死亡结果触发；**玩家个人击杀与友军/NPC/外援战果分开归因**；积分主要用于成绩与即时认可，**不自动兑换代币或连杀空袭**。
- **A-10 的高潮链**：玩家标记→呼叫与确认→飞行员入场通联→标志性机炮扫射声→尸群按真实伤害陆续倒下→屏幕侧高频加分/合并战果→机组返航汇报与战场余韵。要避免预先虚报击杀，也不要把几十条 `+100` 无限制叠在同一位置。
- **现有功能不重做**：`DamagePopup`（✅ L4）、`AmmoHud` 空仓警告（✅ L4）、容器品质揭示动效/光晕（✅ L4）已经存在；后续只讨论增量打磨，不得把它们标为新需求。

#### 3.6.3 军事无线电与战术外援（架构 A、局内 E、音频 G、HUD H、经济 I）

- **通讯沉浸**：玩家呼号请求（如 Bravo Six）→堡垒指挥确认（如 Haven/Overlord）→执行单位（如 Hawg 1-1）回话→实际行动→任务结束回报；无线电接通/断开音、字幕、发言人身份可分阶段逐步加入。
- **同一事件有真实的忙碌状态**：外援连续使用存在内置调度等待；**第一次被拒绝**可以完整无线电解释，短时重复请求**只显示一句有原因的文字**（如「空中支援正在执行其他任务/当前空域繁忙」），不要反复播放语音或只写「无法使用」；提示的空域、ETA 必须与实际规则吻合，而非胡编。
- **支援资源分层**：区分「获得使用权限」「持有可消耗库存/调用次数」「当前是否能执行（冷却、空域、目标、建筑遮挡）」；无效/不可受理请求不提前扣除珍贵库存。支援系统不与个人击杀积分的积累直接捆绑。
- **拟定外援类型**：侦察无人机、攻击无人机、A-10 等攻击机对地扫射、其他重火力；能力各异，而非只是不同倍率的伤害按钮。真实目标与伤害仍服从阵营规则。
- **拟定获得渠道**：正式任务和限时悬赏、局外花费稀有代币购买、世界随机空投/事件概率获取、堡垒长官信任带来的配额或价格待遇；抽取概率、货币价格与长期收益**尚未定稿**。
- **指挥官高信任待遇备选（均非已定数值）**：例如 10 级关系体系中 8 级起每次出击给一次非累积的免费攻击机，**或**采购折扣、**或**提高配额/周期限购（如「每三局可用两次」）；不应默认叠加全部福利，需防止后期经济失衡。
- **投入产出定位**：外援应能显著节省弹药和时间、突破露天尸潮，但不是进入高危区域的强制钥匙；室内目标、恶劣条件等限制必须在确认扣费前明示。

#### 3.6.4 堡垒人物关系、突破任务与长期成长（阶段 8 衔接，经济 I）

- **指挥官信任不会靠无限刷普通僵尸刷满**：初级任务/击杀可提供基础认可，到达门槛后需完成有意义的晋升或突破任务。一个剧情例子是深入危险地点取回长官在危机撤离时遗落的妻子照片。
- **关系不仅是数值**：兼顾专业认可、私人信任与完成过的关键任务；NPC 可依据真实事件改变称呼与语气（机组从「Rookie」到正式呼号与尊重），不靠每升一级统一替换全部语音。机组或其他 NPC 对玩家功绩的议论可成为间接引导。
- **微小但有后果的世界变化**：长官办公桌出现取回的相片，机组在下一次碰面记得玩家曾呼叫空袭，医疗人员记得救援经历，撤离通联根据伤势/任务货物选择变体。优先使用少量状态标记、场景道具和字幕/对白，不必先做庞大 NPC 日常模拟。
- **存档预留建议（非阶段 7 新强制工作）**：未来长期关系级别、关键任务完成标记、首次特殊事件标记、支援授权与库存等需要可持久化的简单数据；设计时与既定 `profile / stash / skills / fort` + `schemaVersion` 对齐，**不在此凭空指定新的已存在字段**。

#### 3.6.5 剧情融入式仓库新手任务（局内 E、容器 F、阶段 8 堡垒衔接）

1. **侧门潜入**：正门尸群密集，侧门较隐蔽；通过环境与敌人行为教会玩家「有时安静绕行比正面交火好」。静步/蹲行尚属 💭，不能写成现有教程能力。
2. **退路受阻**：结构事故导致小门无法倒退，集中初期路线选择；可在仓库内部自由行动，避免大范围软锁或纯粹的强制教学墙。
3. **仓库搜刮**：沿用**已完成的**逐步搜索、物品拾取与品质揭示（✅），找到关键物品即可推进；其他容器不强制搜光，以免教程重复劳动。
4. **正门尸潮困境**：让玩家观察到当前常规火力不足，先建立求援需要；堡垒**本次教学特批一次**空中支援（是否库存豁免需在未来落实）。
5. **手动标记 + A-10 演出**：用激光指示设备标记露天尸群，依 §3.6.2/3.6.3 的真实扫射、语音和击杀成绩完成第一次大型高潮；呼叫**之前**告知这次特别配额宝贵，事后再次提醒珍稀性。
6. **安全撤离与目标发现**：回堡垒后玩家可向指挥官打听如何再次获得攻击机，得知「做任务→赚稀有代币→购买」；离开对话时遇见返航机组，通过自然对白得知「赢得长官信任还会有特殊待遇」，形成另一条长期目标路线。

> **限制**：教程可安排精心控制的首轮战斗高潮，但不代表往后遇到尸潮必须使用外援；后续通过关卡教潜入、绕行、重武器和撤退等替代解法。它是未来的教程构想，不在当前 7 阶段开发清单内。

#### 3.6.6 Raven（渡鸦）濒死精英救援（局内 E、AI D、经济 I）

- **首次揭示**：前期不在教程或菜单中剧透；设想为本存档首次符合条件的正式战局濒死时，触发一次**剧情性自动救援**。解释方案包括「渡鸦恰好在附近执行任务，临时改道」；不能不考虑地图位置便统一声称队伍在三个街区外。首次是否免费及触发边界留待定稿。
- **情绪链**：玩家倒地、濒死且认为已失败→堡垒紧急联络渡鸦→远处无线电与重武器交火逐渐接近→烟雾入场→实际清敌→确认救援区安全→医疗兵复苏→再次投烟、有序撤离→玩家劫后余生。
- **绝非纯播片/假安全窗**：渡鸦成员携带真实武器、遵守 `CanDamage`/`IDamageable`，**实际消灭或压制**玩家周边威胁；以可判定的局部区域安全条件决定何时施救（不必清空全地图），受威胁时继续战斗或中断急救。安全时间来自真实清场，**不另送隐形无敌时间**。
- **复苏后果**：玩家恢复操作，仍可打药、整理弹药与规划撤离；小队不负责代替玩家完成整场撤离。本次战局最大生命值上限持续降低（普通药品无法补回削去的上限），促使玩家尽快撤离；削减比例待测，下一局不应永久损失角色上限，回堡垒的治疗呈现方式待定。
- **死亡边界**：与当前「血量归零→RaidDirector Defeat」的直接结算不同；未来需先区分濒死/可救援、成功复苏、不可救援的真正死亡，且保持 `Victory/Defeat` 互斥与只结算一次。首次剧情救援后不可误导玩家认为之后永久免费。
- **正式申请设想**：高门槛特殊身份/授权（用户称 VIP）、付出显著但合理的游戏内成本，允许放弃本局；是否收代币、专用救援凭证、复合成本及具体数值**尚未决定**。每局限制成功救援次数属于待测试约束，避免有钱即可无限续命，也避免机制昂贵到无人使用。
- **可用性与性能约束**：若长时间无法控制战场威胁，不应无限卡住急救状态；首演可更完整、重复救援可缩短无操作等待。禁用全局 `Time.timeScale = 0`，并确保救援过程真实 AI 与医疗状态按游戏规则推进。

#### 3.6.7 高危地图、撤离与模式联动（局内 E、阶段 6C/9/10）

- **高风险高收益核心区域**：例如疫苗管理中心，包含露天外部防线与室内高价值核心区；有能力者可选择重型武器（榴弹发射器/喷火器为未来设想）、走位控场、安静绕行、撤退路线等方案，**不得把攻击机设计成强制通行证**。
- **战略价值**：一次空袭可清除外围密集威胁、节省弹药与时间，但室内搜索、剩余危险、最终撤离仍由玩家承担；全局昼夜/夜间撤离是已有的**延后阶段 6C**，不得擅自提前插队。
- **撤离反馈微改动**：复用已有直升机阶段与 Toast 事件，以「收到请求→即将到达→落地→登机→安全返回」等世界观无线电语句增强临场感；可根据玩家低血量/关键货物选简短变体。撤离结算将来可增加战果回顾（不取代阶段 7 已排期的入库结算）。
- **守塔模式**：阶段 9 的无惩罚波次环境可用于对比基础射击、受击反馈、击杀积分与高级支援的体验；未来如何跨模式共享资源，以已有设想为准，不擅自定新规则。

| --- | --- | --- |
| 禁用武器槽会不会被选中 | **不会** | `TrySwitchTo` 有 `!slots[index].enabled → return false`（:449）；`FindNextSlotWithAmmo` 跳过禁用（:438）；`GameInput.Slots` 只有 5 个（数字键 1~5 → 下标 0~4） |

| 信号枪"已使用"能否读到 | **不能（缺口）** | `SignalGun._used` 是 private，无公开属性 |
| 装备白名单会不会被绕过 | **不会** | `CanPlaceAt` 里 `IsKindAllowed` 是硬判定，拖拽与 F 快捷拾取共用同一入口 |

| 格子组件能否跨 UI 复用 | **需抽接口** | `ItemCellView` 有 **9 处**直接调用 `InventoryUi`；`InventoryGridView` 只透传 |
