## 1. 目标与非目标

### 1.1 目标

把现有的**临时三列界面**（`InventoryUi.cs`，1552 行，纯代码构建）替换为**接近参考图的正式界面**，同时保住所有已经实机验证过的底层能力。

最终形态（分三步走，**不要一步到位**）：

1. **结构跑通**：分区正确、组件层级正确、真实数据绑定、交互正确 —— 先不追求精致
2. **视觉细化**：深色半透明面板、橙色强调、字体字号、选中高亮、槽位底色、图标
3. **动效与音效**：过渡动画、悬停/点击反馈、音效

### 1.2 非目标（本阶段明确不做）

- 不重写背包/容器/网格算法（规则在 `Core/`，一行不改语义）
- 不做容器物品化（弹挂/背包不能真的拖下来换）
- 不做地面掉落物（T 丢弃）
- 不做死亡保护、护甲减伤、健康状态机制
- 不做负重惩罚（只显示数字）
- 不迁移 HUD（血条/弹药/准星仍是 OnGUI）
- 不引入任何第三方 UI 框架

## 3. 布局规格

### 3.1 画布与适配

- Canvas：`ScreenSpaceOverlay`，`sortingOrder = 100`（与旧 UI 同级，反正不同时显示）
- `CanvasScaler`：`ScaleWithScreenSize`，参考分辨率 **1920×1080**，`matchWidthOrHeight = 0.5`
- 目标分辨率：1920×1080 / 2560×1440（都是 16:9，等比放大即可）
- 非 16:9 窗口：靠锚点自适应，允许左右留白，**不允许元素重叠或裁切**

### 3.2 分区（在 1920×1080 下的目标比例）　⚠️ 已被 §18 覆盖（尺寸改为左 380 / 中 660 / 右 600、格 60px）

```
┌──────────────────────────────────────────────────────────────┐
│ 顶部导航栏 56px   背包 | 任务 | 地图 | 设置        本局获得 +X │
├───────────────┬──────────────────────────┬───────────────────┤
│ 左：角色与装备 │ 中：弹挂 + 背包           │ 右：容器          │
│ ┌───────────┐ │  弹挂 4×2                │  （未开容器时空白）│
│ │角色预览    │ │  ┌────┐                  │                   │
│ │（占位）    │ │  └────┘                  │  打开容器后：      │
│ │           │ │  背包 10×6                │  标题 + 网格      │
│ └───────────┘ │  ┌──────────┐            │                   │
│ 装备槽列：     │  └──────────┘            │                   │
│  头盔/防护服   │                          │                   │
│  近战/特殊道具 │                          │                   │
│ 武器槽 ×3      │                          │                   │
├───────────────┴──────────────────────────┴───────────────────┤
│ 左下快捷栏 │ 中下角色状态（血/负重/状态位） │ 右下安全箱 2×2  │
├──────────────────────────────────────────────────────────────┤
│ 底部键位提示 32px                                             │
└──────────────────────────────────────────────────────────────┘
```

### 3.3 硬性布局约束

1. **右侧容器区恒定占位**：只开背包时右列留空，**不得把左列/中列拉宽** —— 否则"开箱前"和"开箱后"位置不一致，操作手感全乱（这是现有行为，必须保住）。
2. **武器槽不得遮挡角色预览**：预览区与武器槽区上下分区，物理上不重叠（不是靠层级盖住）。
3. **格子大小自适应**：中列背包 10 列、右列容器最多 10 列，若超出可用宽度就**按可用宽度反算 cell**，不允许溢出裁切。
4. 左/中/右三块用**锚点**固定（左贴左、右贴右、中居中拉伸），不写死绝对坐标。
5. 同一行的三个底部面板用水平布局，互不重叠，宽度不足时优先压缩中间状态区。

> 以上是**目标比例**，不是像素铁律。阶段 B 在 Unity 里目视微调，改 Prefab 即可，不用改代码。

### 4.1 `IItemCellHost`（对现有代码的唯一改动点）

`ItemCellView` 现在有 **9 处**直接调用 `InventoryUi`：

```
GetIcon(string itemId)
BeginDrag(ItemCellView, Vector2)
UpdateDrag(Vector2)
EndDrag(Vector2)
SetHoveredCell(ItemCellView)
ClearHoveredCell(ItemCellView)
ShowTooltip(ItemCellView, Vector2)
HideTooltip(ItemCellView)
OnItemRightClick(ItemCellView)
```

把这 9 个签名抽成接口，`InventoryUi` 声明实现它（方法体一个字不改），新 UI 的 `InventoryScreen` 也实现它。

**为什么必须抽**：`ItemCellView` / `InventoryGridView` 是"格子与网格"的唯一实现，新旧两套界面要共用它们。复制一份等于把已经踩过 6 轮坑的拖拽逻辑再写一遍。

**注意**：
- 不能用 `[SerializeField] IItemCellHost`（Unity 不序列化接口）。现有代码全部是 `AddComponent` + `Bind(...)` 传引用，**本身就绕开了序列化**，所以不存在这个问题 —— 但**不要**为了"方便"把它改成 Inspector 字段。
- `InventoryGridView` 只是把宿主透传给格子（`view.Bind(_ui, ...)`），改动量仅 1 行类型。

## 5. 数据层改动（Core，纯 C#，必须配单测）

> 铁律：`Assets/Scripts/Core/` **零 `using UnityEngine`**。加任何东西都先问"这段逻辑放服务器上还能跑吗"。

### 5.1 `ItemKind` 追加 3 个值

现有 7 个：`Misc=0, Weapon=1, Ammo=2, Medical=3, Material=4, Key=5, Card=6`。

追加：`Helmet=7, BodyArmor=8, Melee=9`。

- **只在末尾追加，不改任何已有数值**（无存档系统，零迁移风险；全项目无 `switch(ItemKind)`，不会掉进 default 分支）
- 不新增"饰品/Trinket"：特殊道具槽是信号枪的只读展示位，不是物品容器

### 5.2 `ContainerRole` 追加 `Equipment`

现有：`Carried=0, MapLoot=1, Stash=2`。追加 `Equipment=3`。

**为什么**：装备容器若用 `Carried`，会被 `PlayerInventory.EnsureBuilt` 一起收进 `CarryGroup` → 按 F 快捷拾取会往头盔槽里塞东西、中列也会把装备槽当背包列出来。

**改动后必须核对的四个方向**（用户明确要求）：

| 方向 | 期望 | 怎么保证 |
| --- | --- | --- |
| 快捷拾取 | 只走 `Carried` | `PlayerInventory` 只取 `Carried`，装备组单独建 |
| 界面分类 | 装备区只列 `Equipment`，中列只列 `Carried` | 两组分开渲染，不可能重复 |
| 负重统计 | 装备 + 携行都算 | `负重 = CarryGroup.TotalWeight + EquipmentLoadout.TotalWeight`，**单测断言** |
| 物品转移 | 装备槽之间/与背包之间搬运仍走 `CanPlaceAt` / `TryTransferTo` | 全部是 `ItemContainer`，规则不分叉 |

### 5.3 `ContainerDef` / `ContainerDefinitionAsset` 追加 2 个字段

| 字段 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `Hidden` | bool | `false` | **不实例化**。口袋 / 钥匙卡包设为 true |
| `QuickPickup` | bool | `true` | 是否参与 F 快捷拾取。安全箱设为 false |

两者都要写进 `ToDef()`，并在编辑器校验里给出提示。

### 5.4 `EquipmentLoadout`（新，Core）

职责：**第二个 `CarryGroup`**，装 3 个装备容器。复用现成的 `CarryGroup`（它本来就是"一组容器"的通用外壳），不新造一套。

```
EquipmentLoadout
  ├ 按 Equipment 角色的容器定义建 ItemContainer（幂等，EnsureBuilt）
  ├ Slots（已按 UiOrder 排序）
  └ TotalWeight（给负重显示用）
```

玩家侧 `PlayerInventory` 暴露 `Equipment` 属性，并在 `EnsureBuilt` 里一起建。

### 5.5 `RaidValueLedger`（新，Core）— 本局收益

#### 语义（用户例子已验证）

**相对"开局携带"的实时价值差**，不是流水账。

- 基线：开局瞬间，所有 `Carried + Equipment` 里每一条的 `(uid, 数量, 单价)`
- 只要 uid 在基线里 → 无论丢几次捡几次，**永远算 0 收益**
- 新 uid → 获得
- 基线 uid 消失或数量变少 → 消耗

#### 公式

```
获得 += Σ(当前存在且 uid 不在基线)            价值(数量 × 单价)
获得 += Σ(uid 在基线 且 当前数量 > 基线数量)   (当前 - 基线) × 单价

消耗 -= Σ(基线存在 且 当前已不存在)            基线数量 × 单价
消耗 -= Σ(基线存在 且 当前数量 < 基线数量)      (基线 - 当前) × 单价
```

#### 用例（与用户原话一致，要写成单测）

| 动作 | uid | 本局获得 | 本局消耗 |
| --- | --- | --- | --- |
| 开局带 50000 的枪，丢在地上 | 消失 | 0 | **-50000** |
| 捡回同一把 | 还在 | 0 | **0** |
| 从武器箱摸到 20000 的枪并捡起 | 新 | **+20000** | 0 |
| 开局 30 发子弹打掉 10 发 | 数量 30→20 | 0 | **-10 × 单价** |
| 上局带出、没清理背包又带进来 | 在基线里 | 0 | 0 |

#### 显示规则

- **只有"本局获得"上界面**（顶部栏右侧 `本局获得 +20,000`）
- **"本局消耗"不在任何画面显示**，只作为后台数据（将来做行为画像/分析用），仅经公开属性暴露
- 刷新时机：打开界面时 + 每次物品变动后（不要每帧重算）

### 5.6 现有 `PlayerInventory.ComputeGainsSinceRaidStart` 怎么办

它现在是**按数量**统计、只覆盖 `Carried`。新 UI 需要的是**按价值**、且覆盖装备组。

处理：保留它（不破坏现有调用），新增 `RaidValueLedger` 用同一份基线数据算价值。两者共用 `CaptureRaidStartSnapshot` 记的基线，**不要让它们各记一份**。

| 1 号位 | `slots[0]` | 名称 + 弹药 `弹匣/备弹` + 激活高亮 | 是 → `TrySwitchTo(0,false)` |
| 2 号位 | `slots[1]` | 同上 | 是 → `TrySwitchTo(1,false)` |
| 3 号位 | `slots[2]` | **「战术重武器 / 未装备」**，禁用灰 + 橙色描边 | **否**（禁用槽，不显示成可用） |
| （不显示） | `slots[3]` | 不创建节点 | — |
| 快捷栏 | `slots[4]` | 血包：名称 + **真实剩余个数** + 当前容量% | 是 → `TrySwitchTo(4,false)` |
| 特殊道具槽 | `SignalGunSlotIndex` | 信号枪：名称 + H 提示 + 选中态 + 已使用态 | 是 → 同 H 键逻辑 |

### 6.3 禁用槽不会「意外可用」（已核实）

- `TrySwitchTo` 第 449 行有 `if (!slots[index].enabled) return false;`
- `FindNextSlotWithAmmo` 第 438 行跳过禁用槽
- `GameInput.Slots` 只有 5 个（数字键 1~5 → 下标 0~4）

**所以不需要改切枪机制。** 但 UI 仍必须把 3 号位画成明确的"未装备"，不能让人误以为能按。

### 6.4 `WeaponSlotUIAdapter`（新）

**唯一允许出现 `slots[0]` / `slots[4]` 这种下标的地方。** 其他 UI 组件一律通过它拿数据：

```
WeaponSlotUIAdapter
  ├ WeaponSlotRead GetPrimary()      → { 名称, 弹匣, 备弹, 是否激活, 是否可用 }
  ├ WeaponSlotRead GetSecondary()
  ├ WeaponSlotRead GetHeavy()        → 未装备时 IsEquipped=false, DisplayName="战术重武器"
  ├ ConsumableRead GetConsumable()   → { 名称, 剩余个数(真实), 当前容量, 容量上限 }
  ├ SignalGunRead  GetSignalGun()    → { 名称, 是否激活, 是否已使用 }
  └ int ActiveSlotIndex
```

**规则**：
- 只读，不改控制器的任何状态
- 不用反射、不复制控制器内部数组
- 信号枪靠 `SignalGunSlotIndex` 识别，**不用末尾下标**
- 下标映射写死在这里，其他地方出现魔法下标视为 bug

### 6.5 为 UI 新增的两个只读接口（用户已批准）

| 文件 | 新增 | 为什么必须加 |
| --- | --- | --- |
| `WeaponController` | `public int GetConsumableKits(int slotIndex)` | `ActiveSlotCount` **只返回当前手持槽**的数量。拿着步枪时要显示"血包 ×3"根本读不到。必须返回**真实当前数量**（不是 `startCount`），非法索引/非消耗品槽返回 0，**绝不修改任何状态** |
| `SignalGun` | `public bool HasUsed => _used;` | `_used` 是 private，快捷栏与特殊道具槽都要显示"已使用"。不改 `_used` 本身权限、不改发射逻辑 |

### 6.6 快捷栏点击行为

- 血包格点击 → `TrySwitchTo(4, false)`（等价数字键 5，**只切换、不治疗**）
- 信号枪格 **不在快捷栏**（见 §7）
- 手雷格 **不存在**：E 键实际绑的是 `Interact`（和 F 同键开容器/拾取），项目没有手雷系统。**不造不存在的格子**

### 12.1 目录

```

```

**物品格子不做 Prefab**：`InventoryGridView` 继续用现有运行时对象池生成（每个格子 1 个 `ItemCellView` + 2 个 `Graphic`），Prefab 化没有收益还会拖慢。

### 12.2 生成器规则

菜单：`ZombieExtraction → UI → 1. 生成背包界面 Prefab`

- **只在文件不存在时创建**；已存在则跳过并打印"已存在，跳过"
- 另一个菜单 `UI → 9. 强制重建（会覆盖）` 才允许覆盖，且先弹确认
- 生成后**自动选中**根 Prefab，方便立刻看
- 幂等：重复执行不产生重复节点
- 生成器不写运行时状态、不碰场景（场景接入是另一个菜单）

### 12.3 运行时

```
InventoryScreenHost（挂 Player）
  ├ [SerializeField] GameObject rootPrefab     ← 唯一引用
  ├ 首次打开：找/建场景级 UIRoot → Instantiate(rootPrefab, uiRoot)
  └ 之后：SetActive(true/false) 复用，不重复实例化
```

- `UIRoot`：场景级空物体（不挂在 Player 下），带 `Canvas` + `CanvasScaler` + `GraphicRaycaster`
- `EventSystem` 全局唯一：复用现有"没有就建、有就把 `StandaloneInputModule` 换成 `InputSystemUIInputModule`"的逻辑，**不许两套 UI 各建一个**
- 不把运行时实例存进任何 ScriptableObject

### 18.5 风险与欠账（开工前已知）

1. **双份血包风险**：第 6 批之前，血包只存在于武器槽 5，**不许**在快捷栏再生成一个"血包物品"，否则同一件东西有两份来源（违反单一数据来源）。

### 18.12 修：第三张武器卡压到底部快捷栏（2026-10-25 晚）

**现象**（用户实测）：第 3 张武器卡（重武器）掉到下面，和快捷使用栏重叠。

**根因**：卡片高度写死 120，总高 858；而**列的真实高度取决于窗口比例**——
`CanvasScaler` 在非 16:9 窗口下，画布在参考单位里的高度会**小于 1080**（例如 2560×1400 约 1065）。
列高从 866 掉到 851，内容 858 就压过了底部条。写死高度的布局天生扛不住这件事。

**修法（两层，都是"按实际可用空间算"而不是写死）**

1. **卡片高度动态算**：`cardH = clamp((可用高度 − 上边距 − 卡片间隔) / 3, 88, 132)`，
   可用高度优先取**真实列高**（> 600 才信，否则退回设计高度，防止画布还没布局好时把卡片压扁）。
   另留 6px 安全边。
2. **角色模型高度跟着槽列走**：`previewH = 槽列底 − 起点`，模型不再是"最高的一块"，
   不会再把它下面的卡片整体推下去。

**实测（1080 设计高度）**

```
Slot 列底 472 ／ 模型 212×430 ／ 卡片 344×114.7 @ -482 / -604.7 / -727.3
最后一张底边 842 ＝ 可用底线 842（列高 866 − 18 内边距 − 6 安全边）
```

窗口再矮时卡片会自动压到 88，并打一条 warning 说明"已经压到底了"。

### 18.13 Prefab 化（2026-10-25 晚）—— 「能手动拖每个块」落地

**动机**（用户）："有没有像 UI Toolkit 那样我可以直接手动调整每个组件、按钮位置"。
uGUI 本身就能拖，**前提是先把界面做成 Prefab**；之前是运行时用代码搭的，所以编辑器里看不到、也拖不动。

**做法**

| 文件 | 作用 |
| --- | --- |
| `Editor/InventoryPrefabBuilder.cs`（新） | 生成骨架 Prefab `Assets/Prefabs/UI/InventoryScreen.prefab`（已存在则跳过，不覆盖你调过的）；另一个菜单把它挂到场景里的 `InventoryUi` |
| `InventoryUi.screenPrefab`（新字段） | 配了就用 Prefab 的层级与位置，代码只填内容；**留空自动退回代码搭建**并打 warning |
| `InventoryUi.BindScreen()`（新） | 按路径名绑定节点；`BindTabs()` 给 Prefab 里的页签/关闭按钮补上 `Button` 与回调 |

**Prefab 结构（改结构时这些路径要同步）**

```
InventoryScreen (Canvas + CanvasScaler + GraphicRaycaster)
└ Root (Image + CanvasGroup)
  ├ Header      (Title / TabGroup{Tabs…} / Close)
  ├ BagPage
  │ ├ Columns   (Left / Middle / Right —— 每列下有一个 Content，动态内容塞这里)
  │ ├ BottomBar (QuickBarPanel / StatusPanel / SafeBoxPanel —— 同样各带 Content)
  │ ├ InputHints（左下角按键图标条）
  │ └ HintLabel
  ├ OtherPage   (Placeholder)
  └ DragLayer
```

**可拖 / 不可拖，说清楚**

- ✅ 可拖：三列的位置与宽高、底部三块、顶栏页签、关闭按钮、提示条位置、各面板背景色
- ❌ 不可拖（数量由数据决定，运行时生成）：物品格子、装备槽、武器卡片、网格本体
  → 它们的**容器**（Content）可拖；想调它们的间距/大小，改对应组件里的常量或参数

**自检工具同步升级**

1. 自检现在**优先加载 Prefab** 走真实路径（日志会打印用的是哪条路径）；
2. 修了它自身一个 bug：重叠判定原来用 `position + rect` 拼矩形，换成 Prefab 后画布被 CanvasScaler 缩放（0.87），
   这个拼法会**假报重叠**；改成 `GetWorldCorners` 后正常；
3. 左列内容改为遍历 `Left/Content` 的子节点（原来只看 Left，只能看到一个 Content）。

**验证**：编译 0 错 0 警告、EditMode **191/191**、自检（Prefab 路径）通过 ——
左列 9 块、底部 380/892/600×112、页签组偏移 0px、按键条 10 个子项、无负尺寸无重叠。

**为什么这条缝只在部分窗口出现**（记下来，以后别当成新 bug）

```
CanvasScaler(ScaleWithScreenSize, match=0.5)
  scaleFactor = (屏宽/1920)^0.5 × (屏高/1080)^0.5
  画布参考宽  = 屏宽 / scaleFactor

1920×1080 → 1920×1080   （正好，看不出问题）
2560×1440 → 1920×1080   （16:9，一样）
2560×1600 → 2080×1300   （16:10，画布变宽 → 右列右边空 160）
```

### 18.18 修：容器格子和背包不一致 + 非法拖入装备栏时的"大红块"（2026-10-25 晚）

| 现象 | 根因 | 修法 | 决策 |
| --- | --- | --- | --- |
| 容器单格比背包小一圈 | 容器格子是**按可用宽度反算**的（`clamp(24~72)`），10 列算出 **39**，而背包是 60 | 容器格子**固定 = `cellSize`（60）**；只有极端情况才缩（见下两条兜底）。卡片宽 = `列数 × 60 + 24`，10 列 = 624 | D77 |
| 卡片 624 比右列 596 宽 | — | 卡片允许**向左溢出 42px**（列间隙 12 + 中列右侧空白 30），`cardLeft = min(0, rightW − cardW)`；溢出再多（>12 列的容器）才缩格子，并打 warning 说明原因 | D78 |
| 非法物品拖到装备栏出现一大片红块 | 落点预览框按 **目标格子的 CellSize** 画；装备槽是 104（1×1 容器画成 2×2），于是 1×1 物品画出 104×104 红框，比物品本身大 1.7 倍 | 预览框尺寸取 `min(目标格, 物品格)` = 60，并**居中在目标格上**（位置仍贴合落点）；背包里（60 对 60）行为完全不变 | D79 |

**兜底顺序**（保证"优先一致、极端才能缩"）

```
rcell = cellSize                                   // 60
if 列数 × 60 + 24 > 右列宽 + 42   → rcell = floor((右列宽 + 42 − 24) / 列数)
if 行数 × rcell > 可用高度        → rcell = floor(可用高度 / 行数)
```

缩了就打 `Debug.LogWarning("[库存] 容器「X」放不下 60 的格子，已缩到 N（背包仍是 60）")`，
不让人猜"为什么这里小"。

**实测参考（1920 宽）**

```
右列宽 596 / 中列 636
10 列容器：rcell 60 → 网格 600 → 卡片 624 → cardLeft −28（落进列间隙，不盖背包网格）
4 列容器： rcell 60 → 网格 240 → 卡片 264 → cardLeft 332（靠右列右侧）
背包：     rcell 60（不变）
```

### 18.19 修：预览框位置 + 自检的假报重叠（2026-10-25 深夜）

| 现象 | 根因 | 修法 | 决策 |
| --- | --- | --- | --- |
| 红框大小对了，但**位置偏下、骑在头盔和防护服之间** | 位置按"物品整块尺寸**居中**在落点上"算：`left = (gx + fw/2) × 目标格 − fw × cell/2`。非法拖入时物品 footprint（如 1×2）**比容器（1×1）大**，这个中心点算到了容器外面，于是整体下移并跨格 | 位置改为**以落点那一格的左上角为基准**（`gx × 目标格`），尺寸仍取 `min(目标格, 物品格)`，并把框**夹在容器像素范围内**（`Clamp(0, 容器像素 − 框尺寸)`）。任何 footprint 都不会越界 | D80 |
| 自检报"收益卡片压住弹挂/背包/安全箱" | 自检跑在**非 Play 的编辑器环境**，`VerticalLayoutGroup` 不会自动排 → 所有卡片停在 (0,0)、尺寸还是初始值，世界矩形全叠在一起 | 读几何之前先 `Canvas.ForceUpdateCanvases()` + `LayoutRebuilder.ForceRebuildLayoutImmediate(cards)` | D81 |
| 自检还去找 `Middle/Content/Earnings` | 收益已改成卡片流里的 `Card_Earnings` | 断言改成在卡片流里找 `Card_Earnings`，并改成"卡片之间互不重叠"（同组内不可能重叠，重叠即说明它没被 LayoutGroup 管） | D82 |

**预览框的最终规则（三句话）**

```
尺寸：cell = min(目标格, 物品格)      → 背包 60 / 装备槽 60 / 安全箱 44
位置：左 = gx × 目标格，上 = gy × 目标格   （落点格左上角，不做任何居中）
边界：宽高与位置都 Clamp 在容器像素内      （物品比容器大时也不会跨格）
```

**实测（布局自检，Prefab 路径，4:3 探针画布 1662.8 宽）**

```
三列宽度      左 640 / 中 636 / 右 338.8（右列吃剩余，16:9 下是 596）
中列卡片      4 张（收益 / 弹挂 / 背包 / 安全箱），最宽网格 600，填充率 94%
本局收益卡片  636 × 34  @(318, -17)     ← 卡片流第一张，不再压在弹挂上
左列          立绘 488×967 / 4 槽 104×120 / 重量条 351×22 / 武器条 280×74 ×3
结果          ✅ 通过（无负尺寸、无重叠）
```

**验证**：编译 `error CS` **0** / `warning CS` **0**；EditMode **191/191**；布局自检 ✅。

### 18.20 武器物品化 第一阶段完成（2026-10-28 深夜；D40 拆分落地）

> D40 原计划「武器物品化 + 消耗品物品化 + 弹匣 + loot + 存档升 version」**一批做完**。
> 本轮只做用户当时明确要的那部分：**「把枪从武器槽装到仓库，也可以从仓库装回去」**（拖拽 + 按钮双路径）。
> 弹匣物品化 / loot / 消耗品物品化 / 存档升 version **都没做**——其中「升 version」经复核**决定不做**，理由见下。

**为什么存档不升 schemaVersion**：`SaveService.CheckVersion` 对低版本是**直接拒绝、没有迁移器**，升版本等于把现有存档全部拒之门外。而「加可空字段」不会让旧程序读新档出错——旧档没有 `weaponInstanceId` → 反序列化成空串 → 那条物品就是普通物品。与 `hasWeapons` / `hasLoadout` 完全同一个决定（§12 / §13 已两次验证过这条路径）。

**数据三层（核心设计，别绕）**

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 真源 | `Core/WeaponRoster` + `WeaponInstance` | 有哪些枪、装备在哪、弹匣备弹。**唯一真源**，跨存档 GUID |
| 化身 | `ItemStack.WeaponInstanceId` → `ItemStackDto.weaponInstanceId` | 仓库格子里的"枪"。随 `stash.json` 原子保存（与名册同一文件，不会一边有一边没有） |
| 桥接 | `Core/WeaponItemBridge.cs`（新） | 卸下 = 解槽引用 + 当场造化身；装备 = 撤化身 + 建槽引用。**唯一入口** |

**五个关键决定**：

1. **武器槽 = 5×2 小容器**（营地仓库页左栏，`AllowedKinds={Weapon}`、`MaxStacks=1`）。装备中的枪在槽里是**真实物品块**（图标 + 可拖拽），拖进来 = 装备、拖出去 = 卸下。好处：**`ItemDragController` 零改动**——幽灵、落点预览、R 旋转、就近吸附全部白嫖。这三个容器**不进存档**，每次刷新按名册重建（`SyncWeaponSlots`）。
2. **换枪原子化**：`WeaponRoster.ReturnToStash` 委托（宿主注入"被换下的旧枪怎么落地"）。落不下（仓库满）→ 装备整体失败，槽里原枪一个字节不动。**卸下同理**：先造格子成功才解槽引用。
3. **读档对账**（`Reconcile`，SaveManager 读档后跑）：旧档补格子 / 撤"名册没有或已装备"的幽灵格子 / 去重复格子（防手改存档造出复制枪）。
4. **槽间互换**：拖 A 槽的枪到 B 槽 = 先纯解除 A 的引用，再装备到 B（B 的旧枪经 ReturnToStash 退仓库并带格子）。
5. **物品定义命名约定** `item_<weaponId>`（如 `item_weapon_g36c`），关联只走 `WeaponDefAsset.itemId` 字符串——这个字段阶段 1 就留好了（注释写着"空字符串 = 尚未物品化"），本轮只是接上。

**验证状态**：23:49 编辑器自动编译覆盖前半批 Core 改动 **0 错 0 警告**；后半批（桥接/UI/编辑器工具/16 个新测试）因编辑器占用项目锁未编译。**L1 自查通过，L2/L3/L4 待用户执行**（步骤见速查卡顶部「下一步动作 ⓪」）。
