## 0. 给完全没接触过这个项目的人

**这是什么游戏**：一个 3D 俯视角的单机「僵尸搜打撤」。设计目标是玩家进入一张地图**搜刮物资**，然后设法撤离；死了就一无所有。核心设计是**局内时间系统**（白天怪弱、黄昏压力上来、黑夜必须用信号枪召唤直升机撤离），但目前时间系统尚未实现。

**当前做到哪**：阶段 6A（一局流程闭环）已完成 —— 能进图 → 打僵尸 → 走到撤离点（或信号枪召唤直升机）→ 撤离成功 → 结算 → 再开一局。

> ⚠️ **注意：目前还不能"搜"。** 地图上没有任何可搜刮的物资，也没有拾取、背包、仓库系统。全项目检索 `拾取 / 搜刮 / Pickup / Loot / Inventory / 背包 / 仓库` 只命中两类：① 已弃用的旧脚本 `HealthPickup.cs`（2026-10-19 已改成"5 号位消耗品 + 缠绷带"，保留但不再使用）② 注释里的"将来接物品/背包系统"。
>
> 所以现在的实际循环是「**进图 → 打 → 撤**」，只是"搜打撤"里的后两段。**搜刮属于阶段 7（经济与存档）**，不在 6A / 6B 范围内。

**这份报告讲什么**：只讲阶段 6B 的僵尸 AI。分四步：① 寻路 ② 状态机 ③ 感知 ④ 交互物。前三步已写完，第四步未开始。

## 1. 这一阶段要解决什么问题

### 改造前（阶段 4 的实现）

僵尸只有三条规则：

1. 玩家在 25 米内 → **直线朝玩家走**
2. 距离小于 1.8 米且攻击冷却结束 → 咬一口
3. 位置由代码自己算，撞墙就卡死

三个致命问题：

| 问题    | 玩家的实际感受                   |
| ----- | ------------------------- |
| 不会绕墙  | 躲到掩体后面，僵尸贴着墙抽搐，或者干脆卡死在墙角  |
| 全知全能  | 隔着墙、背对着你，也知道你在哪、正在往哪走     |
| 反应零延迟 | 你刚绕墙跑，它立刻算出"回头堵你更近"，像自动驾驶 |

### 改造目标

不是"让僵尸更强"，而是**让它的"笨"看起来合理**：

- **该会绕路的会绕**（沿场景烘焙好的可行走网格）
- **该看不见的就看不见**（视野角度 + 视线被阻挡）
- **该听不到的就听不到**（声音有传播半径）
- **该迟钝的就迟钝**（转身慢、反应慢、只记得旧位置）

## 2. 代码怎么分层

项目有一条硬规矩：**规则层（Core）必须是纯 C#，不能碰 Unity 的任何东西**（Transform / Time / Physics / Random 全部禁止）。原因是将来如果做联机，这套规则要能原封不动搬到服务器上跑。

所以僵尸 AI 被拆成三层：

```
┌─────────────────────────────────────────────────────────┐
│  Core（纯 C#，无 UnityEngine 依赖）                        │
│  ├─ ZombieConfig        数值配置（速度/血量/范围/记忆时长…） │
│  ├─ ZombieState         状态镜像（血量/冷却/是否在攻击距离） │
│  ├─ ZombieRules         每 tick 算：攻击冷却、能否攻击       │
│  ├─ ZombieBrain         脑子：当前状态 + 最后已知位置        │
│  ├─ ZombieBrainRules    状态机转移（Idle/Alert/Chase/…）    │
│  ├─ ZombieSensesRules   视野扇形判定（只算角度，不管遮挡）    │
│  ├─ NoiseEvent          噪音数据（类型/位置/半径）           │
│  └─ NoiseRules          枪声半径公式 + 能否听见              │
└─────────────────────────┬───────────────────────────────┘
                          │ 读配置 / 问判定
┌─────────────────────────▼───────────────────────────────┐
│  Gameplay（MonoBehaviour，负责"落地"）                     │
│  ├─ ZombieMotor         移动（NavMeshAgent）+ 感知 + 攻击    │
│  ├─ ZombieSpawner       维持场上僵尸数量、出生点吸附导航网格  │
│  └─ NoiseSystem         噪音广播站（环形缓存，谁都能查）      │
│                                                          │
│  Gameplay/ZombieSensesDebug  纯 Gizmos 的可视化（不参与逻辑）│
└─────────────────────────────────────────────────────────┘
```

**一句话分工**：Core 回答"该不该打、看没看见、听没听见"；Gameplay 回答"怎么走过去、射线打到什么、声音从哪来"。

**为什么位置不归 Core 管了**：墙在哪、路怎么绕，这是场景信息，Core 不该知道。所以从阶段 6B 起，僵尸的位置由 Unity 的 `NavMeshAgent` 决定，Core 只是借用"实际位置"来算距离。

## 4. 第一步：寻路

### 做了什么

把"僵尸自己算坐标"换成"Unity 导航网格自动寻路"。

**NavMesh 是什么**：Unity 会分析场景里的可站立表面，烘焙出一张"能走的地方"的地图。`NavMeshAgent` 是一个组件，你告诉它"我要去这个点"，它会自己算出绕过障碍的路径并移动。

### 当前场景的烘焙参数

| 参数              | 值                                                           | 说明                                      |
| --------------- | ----------------------------------------------------------- | --------------------------------------- |
| Collect Objects | All                                                         | 灰盒的 Ground / Wall / Cover 是平级物体，没有共同父物体 |
| Agent Radius    | **0.4 米**                                                   | 必须和僵尸的 `agentRadius` 一致，否则贴墙穿模或走不进窄缝    |
| Agent Height    | 2 米                                                         | 默认                                      |
| 数据文件            | `Assets/Scenes/Test_Graybox/NavMesh-NavMesh.asset`（17.8 KB） | Unity 6 自动放在与场景同名的文件夹里                  |

> Unity 6 的烘焙入口**不在** `Window → AI → Navigation`，而在场景里 `NavMesh Surface` 组件的 Bake 按钮上。旧教程会让你在 Navigation 窗口点 Bake，那个流程已废弃。

### 踩到的四个坑（都在代码注释里）

| # | 坑                     | 后果                           | 修法                                       |
| - | --------------------- | ---------------------------- | ---------------------------------------- |
| 1 | `Freeze()` 只禁用自己      | Agent 的转向逻辑还在跑 → 撤离成功后僵尸继续挪动 | 必须同时 `_agent.enabled = false`            |
| 2 | Awake 时 Agent 默认是开的   | 它会把僵尸瞬移到最近的导航网格点（可能穿进墙）      | 先关掉，对齐位置后再打开                             |
| 3 | `transform` 在胶囊**中心** | 直接贴地会让胶囊半截埋进地里               | 对齐时抬高 `agentBaseOffset`（= 胶囊高 / 2 = 1 米） |
| 4 | 状态在 `Start` 里初始化      | 出生器同帧统计存活数时血量还是 0 → 被当成尸体    | 移到 `Awake`                               |

### 实机验证结果（用户确认）

- 僵尸会绕过 `Wall` 和 `Cover`，不再贴墙卡死
- 不出地、不飞天
- 撤离成功瞬间所有僵尸立刻定格
- Console 无报错，攻击与受伤正常

> 用户当时还提出一个体验问题：*"玩家绕着墙转圈时，僵尸会立刻反应过来回头堵你更近的路线，像开了透视眼"*。这直接促成了第二步。

## 5. 第二步：状态机

### 状态图

```
         看见
  Idle ──────────▶ Alert ──(愣 0.35 秒)──▶ Chase ──(够近)──▶ Attack
   ▲                 │                       │                  │
   │                 └────── 看不见 ─────────┴──── 看不见 ──────┘
   │                              ▼
   │                           Search
   │                              │
   └────(扫视 3 秒没找到)◀────────┘
```

| 状态            | 行为              | 玩家看到的现象         |
| ------------- | --------------- | --------------- |
| **Idle** 待机   | 站着不动            | 像根柱子            |
| **Alert** 察觉  | 站住"愣" 0.35 秒    | 刚发现你时会有个短暂停顿    |
| **Chase** 追击  | 走向**最后看到你的位置**  | 你跑了它才追过去，追的是旧位置 |
| **Search** 搜索 | 走到那个位置后原地扫视 3 秒 | 到了之后会原地转圈找      |
| **Attack** 攻击 | 停下按 1.2 秒间隔咬    | 贴脸时不再乱走         |

### 四个"变笨"的手段

| 手段       | 参数                                | 默认        | 效果                                 |
| -------- | --------------------------------- | --------- | ---------------------------------- |
| 察觉延迟     | `reactionSeconds`                 | 0.35 秒    | 看见你之后先愣一下才动                        |
| 只追最后已知位置 | `memorySeconds` / `searchSeconds` | 5 秒 / 3 秒 | 跟丢后去你最后出现的地方找，找不到就放弃               |
| 转身限速     | `turnSpeedDeg`                    | 240°/秒    | 不瞬间扭头，绕墙时能看出它在拐弯                   |
| 路径重算节流   | `repathInterval`                  | 0.35 秒    | **0.35 秒内不管你怎么跑，它都沿旧路线走** ← 最有效的一条 |

### 实机验证结果（用户确认）

Console 里能完整看到 **「追击 → 搜索 → 待机」** 的转移链，僵尸确实不再追过来（"应该是没问题了"）。

## 6. 第三步：感知（代码完成，待验证）

### 6.1 视觉：三步全过才算"看到"

| 顺序 | 判定                                 | 参数                                | 位置                               |
| -- | ---------------------------------- | --------------------------------- | -------------------------------- |
| 1  | 距离 ≤ 25 米                          | `detectRange`                     | Gameplay                         |
| 2  | 目标与**当前实际朝向**的夹角 ≤ ±60°（即 120° 扇形） | `fieldOfViewDeg`                  | `ZombieSensesRules.IsInViewCone` |
| 3  | 从"眼睛"到"目标"打一条射线，中途被挡 = 没看见         | `eyeHeight` / `sightTargetHeight` | `ZombieMotor.CanSeeTarget`       |

**三个细节值得单独说**：

**① 扇形用的是"平滑后的实际朝向"**，不是"指向玩家的方向"。所以"转身慢"会真的影响感知 —— 你从背后跑过去，它得先把头转过来才看得见。

**② 眼睛高度必须从脚底算，不能从 `transform` 算。** 僵尸的 `transform` 在胶囊中心（离地 1 米）。如果写成 `transform.position + up * 1.5`，眼睛实际在 **2.5 米**高 —— 而灰盒掩体只有 2 米高，射线会从掩体**上方掠过**，掩体形同虚设。正确写法是先求脚底再抬高。

**③ 遮挡射线的实际高度**（修复后）：

- 起点：僵尸脚底 + 1.5 米
- 终点：玩家位置 + 0 米（玩家胶囊中心，约 1.05 米）
- 场景里 Cover 高 2 米、Wall 高 3 米 → 两者都能挡住

### 6.2 听觉：噪音系统

**三层职责分离**：

| 层     | 谁负责                                           | 只做什么                |
| ----- | --------------------------------------------- | ------------------- |
| **发** | `WeaponController`（开枪）<br />`PlayerMotor`（脚步） | 在什么位置、多大声           |
| **传** | `NoiseSystem`（静态）                             | 环形缓存最近 12 条噪音，谁来查都给 |
| **听** | `ZombieMotor` + `NoiseRules.CanHear`          | 按自己的半径判断听不听得见       |

**为什么不用 C# 事件**：事件要处理订阅/退订，僵尸被打死销毁时漏退订就会留下悬挂引用，报错很难查。改成"僵尸每 tick 主动问一句"就没有生命周期问题了。

**枪声半径不是写死的**（这是用户明确的数值设计）：

```
最终影响半径 = 武器自带暴露度 + 所有修正项之和
```

| 例子       | 计算        | 结果   |
| -------- | --------- | ---- |
| 手枪，无消音器  | 10 + 0    | 10 米 |
| 冲锋枪，装消音器 | 20 + (-5) | 15 米 |
| 机枪，无修正   | 28 + 0    | 28 米 |

配置在**每个武器槽**上：`noiseExposure`（自带暴露度）+ `noiseModifiers[]`（float 数组，消音器填 -5）。

**将来加"消焰器""枪管长度""弹药类型"，只往那个数组里加一项就行，一行代码都不用改。**

**当前的噪音源**：

| 来源   | 半径             | 频率      |
| ---- | -------------- | ------- |
| 开枪   | 武器暴露度（默认 10 米） | 每发一次    |
| 走路脚步 | 3.5 米          | 每 0.5 秒 |
| 冲刺脚步 | 8 米            | 每 0.5 秒 |

### 6.3 两个行为细节

1. **视觉优先**：正在追击/攻击时**不听声音**。否则玩家边打边跑，僵尸会在"追人"和"去查声音"之间来回抽搐。
2. **同一位置的声音不重置搜索进度**：脚步每 0.5 秒发一次，如果每次都重置，僵尸会永远停在"刚听到"那一刻，永远不进入扫视阶段。

### 6.4 调试可视化：`ZombieSensesDebug`

挂在模板僵尸上，纯 Gizmos 绘制，不参与逻辑、无运行时开销。

| 图形   | 颜色   | 含义                   |
| ---- | ---- | -------------------- |
| 地面圆  | 🟢 绿 | 视觉距离 25 米            |
| 地面扇形 | 🟡 黄 | 视野 120°（能看出它朝哪、背后在哪） |

## 8. 这一轮踩的坑（4 个，全是"沉默失效"型）

这一类问题的共同点：**不报错、不崩溃、Console 干净，但功能完全不生效** —— 最难查。

| # | 坑                                | 现象                              | 根因                                                                                               |
| - | -------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------ |
| 1 | **场景老组件的新字段读成零值**                | `maxVisible` 变成 0，屏幕上只能显示 1 条提示 | Unity 对已序列化的组件反序列化时**不执行字段初始化器**，缺失字段一律取类型零值                                                     |
| 2 | **`LayerMask` 读成 0 = `Nothing`** | 僵尸**隔墙也能看见玩家**                  | `Physics.Linecast(..., 0)` 不检测任何层 → 永远返回"没被挡住"。Inspector 里显示 `Nothing`，看起来像"没选层"而不像坏了            |
| 3 | **射线起点算在离地 2.5 米**               | 躲在 2 米高掩体后照样被看见                 | `transform` 在胶囊中心，`transform.position + up * 1.5` 的实际高度是 2.5 米 → 射线从掩体上方掠过                       |
| 4 | **朝向被无条件锁定到目标**                  | 墙后生成也会慢慢转头看你                    | Core 里 `if (distance > 0.05f) FacingDeg = Atan2(...)`。**连带后果**：视野扇形以朝向为中轴，朝向永远锁定玩家 → 120° 视野从未生效 |

**沉淀下来的三条纪律**：

1. **新增字段一律做兜底**：数值型 `<= 阈值 → 默认值`；`struct`（`LayerMask` / `Color` / `Vector2`）`== 0 → 默认值`；`bool` 一律定义成"**false 是安全的那一侧**"（要关功能就写 `disableXxx = false`，不要写 `enableXxx = true`）
2. **凡"眼睛 / 枪口 / 头顶"的高度，先确定基准是脚底还是 pivot**，并写进 Tooltip
3. **任何"朝向 / 位置"类的自动跟随，都要问一句"它凭什么知道"** —— 信息不足时保持原状，而不是无条件朝向目标
