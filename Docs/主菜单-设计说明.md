## 3. 布局契约（用户明确要求"位置不要写死"）

1. **所有尺寸/颜色只来自 `MenuTheme`**（`[Serializable]`，主菜单对象上可在 Inspector 直接改）。
   页面脚本里**不出现魔法像素**，只有相对关系。
2. 区域一律用**拉伸锚点 + 四边偏移**（`offsetMin/offsetMax`）表达"离父节点各边多远"。
   不用 `sizeDelta` 直接写宽高（拉伸锚点下 `sizeDelta` 语义是"相对父节点的增减"，极易算错，
   曾经写出负尺寸导致节点完全不渲染）。
3. 画布用 `CanvasScaler.ScaleWithScreenSize`（参考 1920×1080、match 0.5），
   所以 `MenuTheme` 里的像素值在任何分辨率下都是**同一个比例**。
4. **格子只有一个尺寸参数**：`MenuTheme.cellPrimary` 同时给背包 / 弹挂 / 口袋 / 钥匙卡包 / 安全箱 / 仓库用。
   仓库列宽不手填，按「仓库格数 × cellPrimary + 内边距」算（见 §12）。
5. 拿到示例图后要改的东西：`MenuTheme` 的字段 + 各页面内部的相对位置。
   **逻辑（按钮回调、搬运、存档）不用动。**

## 4. 营地为什么需要"装备架"

仓库页中间那两栏是**真网格**（要读格子、要拖物品），需要一个真实的 `CarryGroup`。
但营地里没有 Player。所以 `MainMenuScreen` 会造一个只挂 `PlayerInventory` 的离线对象
（`CampInventory`）：

- 它同样走 `EnsureBuilt` → **从存档恢复 loadout**；
- 营地不属于战局（`RaidDirector.Running == false`），自动保存会**把 loadout 写回**；
- 进图前 `MenuFlow.EnterRaid` 还会 `SaveNow` 一次，保证战局拿到的是最新装备。

## 5. 设置：哪些真生效，哪些灰掉

**硬规矩**（用户选的 2A 策略）：**只做真能生效的开关**；做不到的显示为不可用并写明原因。
假开关比没有更糟 —— 玩家以为调了，实际没变。

| 项 | 状态 | 说明 |
|---|---|---|
| 显示模式 / 分辨率 / 垂直同步 / 最大帧率 | ✅ | `Screen` / `QualitySettings` / `Application.targetFrameRate` |
| 画面质量 | ✅ | 只有 2 档（Mobile / PC），来自 `QualitySettings.names` |
| 纹理质量 | ✅ | `QualitySettings.globalTextureMipmapLimit` |
| 主音量 | ✅ | `AudioListener.volume` |
| 改键（开火 / 瞄准 / 换弹 / 交互 / 背包 / 信号枪） | ✅ | 复用 `GameInput.StartRebind`，显示名走新增的 `GetBindingDisplay` |
| 渲染分辨率 / 阴影质量 | ❌ | 要改 URP 资产（`PC_RPAsset`），运行时会**改脏资产文件** |
| 后期效果 / 动态模糊 | ❌ | 项目里没有 Volume / 后处理组件，没有对象可调 |
| 音效 / 音乐音量 | ❌ | 没有 `AudioMixer`，无法分总线 |
| 瞄准方式 / 冲刺方式 | ❌ | 要改输入层（`AimHeld` 直接读物理键） |
| 伤害数字 / 镜头晃动 / HUD 缩放 / 准星样式 / 字幕大小 | ❌ | 缺对应的系统或统一入口 |
| 语言：英语 | ❌ | 无本地化系统（文案全硬编码） |
| 辅助功能四项 | ❌ | 屏幕震动、连点、UI 主题、色盲配色都还没有 |

**设置存在 `PlayerPrefs`（键前缀 `zx.settings.`），不进存档文件。** 理由：

- 设置是"这台机器的偏好"，不是游戏进度；
- 存档有 `schemaVersion` 校验，**升版本会让玩家现有存档直接读不出来**
  （`SaveService` 对"版本低于程序且无迁移器"是拒绝读取）——
  为一个音量开关冒"老档打不开"的风险不值得；
- 键位改绑本来就已经在 `PlayerPrefs` 里（`zx.input.*`），放一起反而一致。

编辑器里**启动时不会套用分辨率**（`#if !UNITY_EDITOR`）：否则每次进 Play 都会把 Game 视图
改成存档里那档，很干扰调试；手动改设置时仍然立即生效。

## 11. 实测修复：仓库页右栏整块不可见（坑 #39）

**现象**（用户 2026-10-24 首次 Play）：切到「仓库」页，左栏（角色占位）与中栏（背包/弹挂）都在，
**右边一片空**，看不到仓库网格，也没有「仓库」标题与条数。

**根因**：`MenuPage.Region(name, host, anchorMin, anchorMax, left, bottom, right, top)` 里
`offsetMin.x = left`、`offsetMax.x = -right`，即 `left/right` 是**向内缩进**。
对拉伸锚点这没问题；但右栏锚点在水平方向是**点**（`anchorMin.x == anchorMax.x == 1`），
此时宽度只由这两个偏移的**差值**决定：

| 写法 | offsetMin.x | offsetMax.x | 实际宽度 |
|---|---|---|---|
| 原来：`left = +560, right = 0` | 560 | 0 | **−560（负）** |
| 正确：`left = −560, right = 0` | −560 | 0 | 560 |

负宽度的 `RectTransform` 不会报任何错，只是**整块不渲染**；而且它的左边界落在 host 右边界
**之外 560 px**（屏幕外），所以里面的网格连"半截"都看不到。
左栏之所以正常，是因为它恰好写了 `right = -320`（负负得正）—— 属于**靠符号凑**，不该留。

**修法**：`MenuPage` 新增 `SideColumn(name, parent, width, rightSide)`，语义是
「固定宽度、贴左/贴右、上下拉伸」，宽度永远传正数，不碰 inset 的符号。
`StashPage` 的左栏与右栏都改用它；中栏（左右都让开一栏 + 间距）仍走 `Region`，因为它是真拉伸。

**顺带修正**：`BuildCarryColumn` 里原来靠 `host.GetChild(host.childCount - 1)` 反查刚建的标题节点，
改成直接用 `MenuUi.Label` 的返回值 —— 以后 Label 内部多建一个子物，旧写法就会拿到错的节点。

**为什么之前没测出来**：EditMode 测的是 Core 逻辑，`MenuPage`/`StashPage` 在 `Assembly-CSharp` 里，
测试程序集只引用 `ZombieExtraction.Core` → **UI 布局没有自动化覆盖**，只能实机看。
结论：这类"算出负尺寸"的问题，**验收清单必须真的看一眼每一个栏位**，不能只看"页面没报错"。

**加了一道护栏**（`MainMenuScreen.CheckNegativeRects`，编译期只在 `UNITY_EDITOR || DEVELOPMENT_BUILD` 生效）：
每次切页后等一帧，扫该页所有 `RectTransform`，**尺寸小于 0 就 `LogError`** 并打出节点路径（最多列 8 个）。
只查负值、不查 0 —— 尺寸为 0 的空占位是正常的。
这样以后按示例图重排、哪一块又算成负的，Console 会直接点名，不用再靠"这一栏怎么没了"来发现。

**复测点**（已并入 §9 第 4 条）：右栏应出现「仓库」标题 + 「主仓 N 条 · 20×15」+ 20×15 网格，
且网格整体落在窗口内（右边缘距窗口右边约 40 px 的留白）。

## 12. 格子尺寸统一 + 小容器命名（2026-10-24 实机第 2 轮）

### 12.1 为什么之前仓库格子比背包小

第一版给三栏各配了一套格子尺寸（背包 44 / 弹挂 34 / 仓库 26），**26 是从"20×15 要塞进 560 px 右栏"
反推出来的**，不是设计选择。后果：

- 一格的语义是"一格空间"，同一种物品在仓库和背包里**视觉大小不一致**，看着像两个系统；
- 玩家会误判"背包一格比仓库一格大"，对容量判断失真；
- 三个数值没有任何约束关系，以后改仓库尺寸（比如 24×18）还得手算一遍并同步右栏宽度。

### 12.2 现在的做法

- `MenuTheme.cellPrimary = 36`（**唯一真值**，背包/弹挂/小容器/仓库共用）；删掉 `cellSecondary`、`cellStash`。
- 仓库列宽**不手填**：`stashWidth = 仓库宽 × cellPrimary + outerPadding` → 20×36+28 = **748**；
  `stashRightWidth` 字段删除。以后改仓库格数，右栏自动跟着变。
- 场景 `MainMenu.unity` 里已序列化的旧值同步改（`cellPrimary: 36`，移除另外三项）——
  `theme` 是 `[Serializable]` 且场景存过，**改 C# 默认值不会影响已存的场景**（速查卡坑 #12）。
- `StashPage.CellSize` 带兜底（`> 0 ? cellPrimary : 36`），防止哪天场景里读到 0 导致整页格子塌成 0 尺寸。

**1920×1080 下的实际数值**（`Content` 宽 = 1920 − 28 − 300 − 18 − 28 = 1546）：

| 区域 | 尺寸 |
|---|---|
| 左栏（角色占位 + 武器槽） | 320 宽 |
| 中栏（随身容器） | 442 宽 |
| 背包 | 10×6 格 × 36 = **360×216** |
| 弹挂 | 4×2 格 × 36 = 144×72 |
| 仓库 | 20×15 格 × 36 = **720×540**，右栏 748 |

为什么是 36 而不是 44：44 时仓库要 880 宽，中栏只剩 290，背包 440 放不进去；
26 又太小（图标与品质底色看不清）。36 是"仓库放得下 20 列 + 背包不缩太多"的交点。

### 12.3 弹挂下面那几个没名字的小格子

它们是**真实容器**，不是装饰，来自 `Assets/Data/Containers/` 里 `role = Carried` 的定义：

| 容器 | 尺寸 | 说明 |
|---|---|---|
| `container_pocket` 口袋 | 1×1 | 快捷使用栏的来源容器 |
| `container_keypouch` 钥匙卡包 | 1×2 | 放钥匙/门卡 |
| `container_safebox` 安全箱 | 2×2 | 死亡不掉落（`deathSafe`） |

之前**只给前两个大容器画了标题**（代码注释写着"标题由外层统一画"，但外层只处理了 `i < 2` 的分支），
于是界面上就是几个无名字的小方块 —— 玩家看不出是什么。这是漏写，不是设计。

现在：`i >= 2` 的每个小容器都画名字，列宽取 `max(格子总宽, 64)`（保证「钥匙卡包」4 个字不压到右邻），

## 13. 进主菜单时报「[存档] 没有 ItemDatabase」——执行顺序造成的假错误（坑 #40）

**现象**（用户 2026-10-24 第 3 轮，只出现一次）：

```
[存档] 没有 ItemDatabase，仓库无法建立（物品定义全查不到）。下次访问会重试 ……
SaveManager:EnsureLoaded() → SaveManager:Awake() → GameObject:AddComponent<SaveManager>()
→ SaveManager:EnsureExists() → MainMenuScreen:Awake()
```

**根因**：`SaveManager.EnsureExists()` 发现场景里没有宿主 → `host.AddComponent<SaveManager>()`，
**`Awake` 同步执行**，而 `MainMenuScreen` 必须等 `AddComponent` **返回之后**才能把 `ItemDatabase` 注入进去。
`Awake` 里无条件 `EnsureLoaded()`，那一刻 `database` 必然是 null（营地里也找不到 `PlayerInventory` 可借），
于是报错并保持"未加载"；`MainMenuScreen` 随后再调一次 `EnsureLoaded()` 才成功 —— 所以**功能是对的，只有一条假错误**。

**修法**：
1. `SaveManager.Awake`：改成"**有引用才初始化**"（`if (database) EnsureLoaded();`），新增 `Start()` 兜底重试
   （`Start` 一定晚于调用方的注入代码）；
2. `MainMenuScreen.Awake`：`EnsureExists()` 返回后**先注入再调用**
   （`if (Saves.database == null && database != null) Saves.database = database;` 然后 `EnsureLoaded()`）。

**通用规律**（已写进速查卡坑 #40）：`EnsureExists()/AddComponent` 工厂 + `Awake` 里读外部引用，是一对必然踩的组合。
要么 `Awake` 只做自给自足的初始化，要么把初始化推到显式的 `Init()` / `Start()`。

**验证**：本轮改动**未跑编译/回归** —— 用户当时开着 Unity 编辑器（`MainMenu` 场景），
batchmode 无法占用同一个工程（`似乎有另一个正在运行的 Unity 实例打开了此项目`）。
脚本改动会被编辑器自动重编译，请在 Console 确认这条错误不再出现；需要我补跑 batchmode 时说一声（先关编辑器）。

## 14. 拖拽只有一份实现 + 删掉旧结算提示 / 临时仓库窗（2026-10-24 第 4 轮）

**用户三条要求**：① 删掉老的死亡提示与撤离成功提示；② 主菜单拖动"有时卡手"、移动中按 R 不旋转（停下才行）；
③ **战局内战局外，背包/容器/仓库的拖放与按 F 移动逻辑必须完全一样**。

### 14.1 为什么按 R "没反应"（只在鼠标移动时）

营地仓库页原来自己写了一份拖拽。拖拽中 `UpdateDrag` 会被调用**两次**：网格的 `OnDrag`（鼠标动时）
和页面 `Update`（为了让鼠标不动也能按 R）。而 `RotatePressedThisFrame` 在同一帧内多次读取**都返回 true**，
于是那份实现把朝向**翻转两次 = 回到原样**。鼠标不动时只有 `Update` 调一次 → 表现"停下按 R 就正常"。

战局内 `InventoryUi` 早就修过这个问题（`Time.frameCount != _lastRotateFrame` 去重），营地那份没同步 ——
**同一段交互逻辑有两份实现，就一定会这样漂移**。同时营地那份没有落点预览框，玩家看不到"松手会落在哪"，
只能凭幽灵位置猜，这就是"卡手"。

### 14.2 统一实现：`Gameplay/Inventory/ItemDragController.cs`

新增一个普通类（不挂 MonoBehaviour），把战局内那套完整逻辑整体搬进去：
幽灵（品质底色 + 首字）、落点预览框（绿/红）、R 同帧去重、`TryResolveDrop` 四级落点、自动转向提示、
就近吸附提示、`ScreenPointToLocalPointInRectangle` 换算（Overlay / Camera 都对）。

宿主只注入两件事：

| 注入 | 战局内 `InventoryUi` | 营地 `StashPage` |
|---|---|---|
| `findGridAt` | 容器列优先，然后随身各格 | 仓库优先，然后中栏各格 |
| `Commit` | `TryMove` / `TryTransferTo` + **搜索队列 `SyncEntries`** | `TryMove` / `TryTransferTo` + `MarkDirty` |

生命周期：`Begin`（OnBeginDrag）→ `UpdateDrag`（OnDrag）→ **宿主每帧 `Tick()`** → `EndDrag` / `Cancel`。
落位失败**不弹窗**（两边都是"松手即取消、物品留在原处"），提示只出现在落点那一行。

### 14.3 F 与右键也统一

| 行为 | 统一后 |
|---|---|
| F：容器/仓库 → 身上 | 顺序**统一走 `pickupOrder`（背包 → 弹挂 → 口袋）**。原来 `PlayerInventory.TryTakeToBody` 按 `UiOrder`（弹挂最前），所以"从箱子拿"进弹挂、"从仓库拿"进背包 —— 同一个玩家做同一件事，落点不同 |
| F：身上 → 容器/仓库 | 都是"搬到对面那一组"，失败提示带原因 |
| 右键 | **与 F 同效**。战局内原来只是打一条日志（占位），现在走同一段代码 |
| 拖拽中按 F | 两边都忽略（左键还按着，再搬会让幽灵和真实物品对不上） |

顺序表里没列到的容器（以后新增）在 `TryTakeToBody` 里会兜底扫一遍，否则它们永远收不到东西。

### 14.4 删掉的旧界面 / 旧代码

## 15. 视觉三改：拖拽只拖图标 / 物品底色 / 悬停只显示名称与价格（2026-10-24 第 5 轮）

### 15.1 拖拽时只拖图标，且略微放大

**之前**：跟随鼠标的是一个"小格子"——品质底色块 + 名称首字；而原格子里**还留着图标**，
于是拖起来像"两个方块"，还带着底色和数量，很吵。

  不能只把 `enabled` 翻回来，否则数量文字会一直不出现。
- 没有图标的灰盒物品退回首字（26pt），仍然是"只有内容、没有底色"。

### 15.2 物品底色改成指定的深色

用户给定（均为不透明）：

| 品质 | 色值 |
|---|---|
| 白 Common | `#555C62` |
| 绿 Uncommon | `#3D5C55` |

**关键改动**：`ItemQualityPalette` 拆成两张表 ——
- `BackgroundColors`（上面这批深色）→ 只用于**物品块背景**，`alpha = 1`（色值不能被半透明稀释）；

### 15.3 悬停只显示名称和价格

**用户追问："为什么我在仓库鼠标悬停没有显示窗口"** —— 因为之前只有战局内画了浮窗；
F1 仓库窗和营地仓库页只是把文字写到界面**底部那一行**，没有"窗口"。

| 位置 | 之前 | 现在 |
|---|---|---|
| 战局内 | 自绘浮窗（320×150，带品质色带） | 共享浮窗 **260×88**，只有名称 + `¥总价` |
| F1 仓库窗 | 底栏一行字 | **浮动窗口**（底栏还给操作反馈） |
| 营地仓库页 | 中间栏底部一行字 | **浮动窗口**（那行只留给拖拽落点提示） |

跟随鼠标右下 18px，四边夹住不出屏；拖拽中不显示（否则信息窗跟着幽灵乱飘）。
价格取**总价**（`单价 × 数量`）。品质、尺寸、重量、单格价值、搜索耗时全部不再显示。

### 15.4 复测点

1. 拖一件物品：**只有图标**跟着鼠标，比格子里的图标略大；原格子只剩淡底，没有重复图标；放下后数量/首字都恢复。
2. 六种品质的格子底色分别对得上上表；相邻物品之间仍有 1px 缝（底色不透明也不会连成一片）。
3. 悬停任一物品（**战局内 / F1 仓库窗 / 营地仓库页三处都要试**）：对话框跟着鼠标、只显示**名称 + 价格**，
   没有品质色条；拖拽时不弹。
4. 六种底色是否够分明（白 `#555C62` 与紫 `#4A4562` 最接近，若还是分不清可再拉开）。

### 15.5 顶栏那串 `d7222bf20994` 是什么（2026-10-24 追问）

是 **`SaveManager.PlayerId` 的前 12 位**。`PlayerId` 在首次启动时由
`Guid.NewGuid().ToString("N")` 生成一次并存进 `PlayerPrefs`（键 `zx.save.playerId`），
顶栏为了不占地方只截前 12 个字符 —— 所以显示的是一段十六进制 GUID 片段，对玩家毫无意义。

**处理**：顶栏改成固定显示「本地玩家」。`PlayerId` 仍然写进存档与日志（多存档、以后联机都要用），
只是不再出现在界面上。将来要做"角色名"时，在这里换成一个可配置的名字即可。
