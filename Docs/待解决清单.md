## 1. ✅ 准星与白线不重合（方案 B）—— 已实现，待实测

### 现象
准星压在 A 点，白线终点落在 A 点**上方约 1.24 米**（屏幕上约 90~95 像素）。距离越近越明显。

### 根因（已定位）
| 环节 | 位置 | 取的值 |
|---|---|---|
| 准星 | `CrosshairHud.cs:75 / :114` | 鼠标屏幕像素，不与任何世界点绑定 |
| 朝向 | `AimInputReader.cs:61` | 相机射线 × **y = `transform.position.y` 的水平面** |
| 射线 | `WeaponController.cs:914-918` | 起点 `muzzle`（局部 0.16, 1.24, 0.5），方向 `transform.forward`（水平） |

落差 = 1.24 米。

**回归来源**：把胶囊原点从腰归到脚底那次改动。改前瞄准平面在 1.0 米（落差 0.24 米），改后落到地面（落差 1.24 米）。

### 方案（已定，2026-10-27 19:05 开工）
1. `AimInputReader` 新增：
   - `Vector3 AimPoint`：**相机射线命中真实碰撞体的点**
   - `Collider AimHitCollider`：相机射线命中的碰撞体（给爆头判定用，B 之前可为 null）
   - `LayerMask aimMask`（默认全部，玩家自身会自动跳过，不用手配）
   - 兜底：相机射线什么都没打到时，退化用「脚底 + `fallbackPlaneHeight`」的水平面交点
2. `WeaponController.ComputeRay`：
   - 方向 = `(AimPoint - muzzle.position).normalized`，**保留 Y 分量**（爆头需要）
   - 回退到 `transform.forward` 的条件：aimPoint 距枪口 < `minAimDistance`（默认 1.2 米）／ aimPoint 在身后
   - `useMuzzleForward` 降级为"没有 aimPoint 时的备选"
3. 身体 yaw 仍只用水平分量（身体不跟着抬头）

### 白线长度：**保持原样**（用户 19:20 明确要求）
不做"未命中时把白线截到准星落点"这个改动。白线永远是一条射向远方的完整射线，命中时才止于命中点。
**`ResolveShot` 一行没动。**

### 地面不参与准星落点（19:25 加）
只恢复长度还不够：如果准星落在空地上，照地面算方向，弹道会俯冲进地面、白线缩成一小截斜线。
所以要**把地面从"准星落点"里排除**：

```
命中条件：法线朝上（normal.y ≥ floorNormalY，默认 0.7）
        且 不是可伤害目标
        → 判定为地面，忽略
```

排除之后，准星落在地面时改用「胸口高度退化平面」的点——那个点**同样在准星射线上**
（投影回屏幕还是准星位置），但方向接近水平，白线就恢复成"伸向远方"。

僵尸头顶不会被误判成地面：它是可伤害目标，被"不是可伤害目标"这一条保住了。
`floorNormalY` 设 0 可关闭这个规则。

### 验收
3 / 8 / 15 米、不同墙角度，白线端点压在准星上（误差 < 5px）；站/蹲/冲刺/切枪后依然重合；贴脸不往身后开枪。

### 实际改动（2026-10-27 19:20）
| 文件 | 改了什么 |
|---|---|
| `Gameplay/AimInputReader.cs` | 新增 `AimPoint` / `AimHitCollider` / `aimMask` / `maxAimDistance` / `fallbackPlaneHeight` / `fallbackDistance`；改用 `Physics.RaycastNonAlloc` 求落点（跳过玩家自身），打不到东西时退化到「脚底 + 1.2 米」水平面 |
| `Gameplay/WeaponController.cs` | 新增 `minAimDistance`（1.2 米）+ `TryAimDirection()`；`ComputeRay` 两个分支都改为朝 `AimPoint` 走（保留 Y）。**白线长度逻辑未改** |
| `useMuzzleForward` | 降级为"没有可用落点时的备选"，不再是主路径 |

### 实测要点（下次进 Play 照这个看）
1. 对着墙站 3 / 8 / 15 米各看一次：白线末端应压在准星上
2. 对着空地（鼠标指地面）：白线仍然**伸向远方**（保持原样，不要截短）
3. 鼠标指天空：不会崩，落点退化成胸口高度的平面点
4. 冲刺 / 换弹 / 切枪后各看一次，仍然重合
5. 贴着墙瞄准：不会出现朝身后开枪（`minAimDistance` 兜底）

### 尚未验证的风险
- `IsAimBlocked`（准星变红禁止）现在基于新方向计算，友方目标判定需要复测
- 弹道有了 Y 分量，**近距离打地面的白线会斜向下**，这是正确行为但视觉上需要适应
- `minAimDistance = 1.2 米` 是估的，贴脸时如果发现"白线不跟准星"，就是落点太近触发了兜底

## 3. ⬛ 准星抖动反馈 + 武器散射

> **2026-10-27 19:45 视觉部分已完成（抖动 + 张开）**，判定层的散射仍未做。
>
> | 已做（纯表现层，`CrosshairHud`） | 参数 |
> |---|---|
> | 后坐抖动（整体位移，指数回落） | `Recoil Kick`(5) / `Recoil Decay`(14) / `Recoil Up Bias`(0.5) / `Recoil Max Offset`(18) |
> | **连射张开**（四条线往外张，停火收回） | `Recoil Spread`(2.5/发) / `Recoil Spread Max`(9) |
>
> ⚠️ **它们都是纯视觉的**：子弹仍然精确飞向准星落点，准星却在抖/张。
> 连射时会出现"准星张开了但子弹还是准的"。
> 等真正的**散射**做完，两者才会一致 —— 那时候张开量要改为由散射角换算。

### 要做的
- **武器散射**：连续射击时子弹方向在锥形范围内随机偏移，连射累积、停火恢复
- **准星抖动/张开**：准星十字臂随散射变大而张开，代表"现在不准"

### 关键约束（这条必须守住）
> **准星显示的散射范围，和判定用的散射角，必须是同一个数值。**

否则会重演"准星和白线对不上"——玩家看着准星张开这么大，子弹却飞出界，比现在还糟。

做法：散射角 `spreadDeg` 只在**一处**计算（规则层或表现层持有），准星把角度换算成像素半径，判定按同一角度加随机偏移。

### 技术要点
- `ComputeRay` 现在出的是单条直线 → 散射 = 方向上加一个圆锥内随机偏移（`Random.insideUnitCircle` 映射到切线基向量）
- 累积模型：每次开火 `heat += step`，停火后 `heat` 按指数衰减；`spread = baseSpread + heat × maxExtra`
- 像素换算：`半径px ≈ tan(spreadRad) / tan(fov/2) × 屏幕半高`
- 需要新增参数：`baseSpreadDeg`、`spreadPerShotDeg`、`maxSpreadDeg`、`recoverPerSecond`

### 待定
- [ ] 散射是**纯水平**（俯视角常见）还是**带垂直**
- [ ] 蹲下/瞄准时是否减小散射
- [ ] 是否要"首发必准"（第一发不加散射）

## 6. ⬜ 音频总线分组（AudioMixer）

### 目标结构
玩家听到的每一路声音都要能单独调，但设置页只暴露少数几个滑块：

```
Master                     ← 总音量（滑块）
├── Music                  ← 背景音乐（滑块）
├── SFX                    ← 音效总开关（滑块）
│   ├── Weapon             ← 枪声 / 换弹 / 空仓咔哒
│   ├── Impact             ← 命中反馈（血肉 / 金属 / 爆头音）
│   └── Footstep           ← 脚步
├── Ambience               ← 环境底噪（单独一条，不受音效滑块影响）
└── UI                     ← 按钮 / 菜单（滑块）
```

**关键点**：`Weapon` / `Impact` / `Footstep` 是 SFX 的**子总线**——它们的**相对音量在 Mixer 里调一次**，
玩家只用 SFX 那一个滑块整体控制。这样既分得清，又不用给玩家 8 个滑块。

### 现状（实查）
| 项 | 状态 |
|---|---|
| `Assets/Audio/Mixers/` | **空目录**，没有任何 mixer |
| `AudioService` 的 4 个 group 字段 | 全部 `{fileID: 0}`（空） |
| 实际用到的 group | 只有 `weaponGroup`（枪声/换弹/空仓全走它） |
| 主音量 | 走 `GameSettings.SetMasterVolume` → `AudioListener.volume` |
| 设置页 | `主音量` 可用；`音效音量`/`音乐音量` 是**灰的占位**（`SettingsPage.cs:191-192`） |
| 脚步 / 命中 / 环境 / 音乐 系统 | **都还不存在**，总线先备好 |

### 阻塞点：Unity 不开放脚本创建 AudioMixer
`AudioMixer` 和它的 Group / Exposed Parameter 都只能通过编辑器界面创建（相关 API 在 `UnityEditor.Audio` 内部命名空间，用反射能 hack 但不稳定，不建议）。

所以流程必须是：
1. **你手工建一次**（约 5 分钟，见下方步骤）
2. **工具自动绑定**（按名字找 group → 填进 `AudioService` 字段）

### 手工创建步骤（建好后我来接线）
```
Project 右键 → Create → Audio Mixer → 命名 MainMixer → 存 Assets/Audio/Mixers/
双击打开 → 底部 Groups 面板，选中 Master，点 + 依次加：
    Music、SFX、Ambience、UI
再选中 SFX，点 + 加：Weapon、Impact、Footstep
选中 Master → Inspector 里 Volume 右键 → Expose 'Volume (of Master)'  → 改名 MasterVolume
    （Music / SFX / Ambience / UI 各做一遍：MusicVolume / SfxVolume / AmbienceVolume / UIVolume）
```
`Exposed Parameters` 在 Mixer 面板**右上角**，改名就在那里改。

### 需要改的代码（等开工）
1. `AudioService`：分组字段扩成 `musicGroup / sfxGroup / weaponGroup / impactGroup / footstepGroup / ambienceGroup / uiGroup`
2. `GameSettings`：新增 `MusicVolume` / `SfxVolume` / `UIVolume`，写入 `AudioMixer.SetFloat`
3. `SettingsPage`：把两个灰色占位换成真正的滑块（`CycleRow`）
4. 主音量从 `AudioListener.volume` **改走 Mixer 的 Master**（两套并存会双重衰减）

### 两个坑（必须记住）
- **dB 换算**：Mixer 的 Volume 是分贝，不是 0~1。线性值必须转：
  `dB = Mathf.Log10(Mathf.Clamp(v, 0.0001f, 1f)) * 20`。直接把 0~1 塞进 `SetFloat`，音量会几乎没有变化
- **`AudioListener.volume` 和 Mixer Master 是乘算关系**：两个都调会变成"平方衰减"，听起来像音量键失灵

- [ ] SFX 子总线（Weapon / Impact / Footstep）的相对音量初值——建好之后要凭耳朵调一次

### 20:30 「动作做完声音还在响」—— 时间线溢出的根因

用户的换弹时长是 **G36C 1.0s / M4A1 1.3s**，而三段真实录音的段长是
**拔弹匣 0.43s、插弹匣 0.51s、拉枪机 0.47s，合计 1.41 秒**。旧时间点
（0.26 / 0.55 / 0.88）在 1.0 秒下的实际时间线：

```
0.26 ~ 0.69   拔弹匣
0.55 ~ 1.06   插弹匣   ← 和上一段重叠 0.14s
0.88 ~ 1.35   拉枪机   ← 超出换弹结束 0.35s
```

**「动作做完了声音还在响」就是这个 0.35 秒。**

#### 约束公式（以后调时间点直接套这个）
```
最后一段：  t × 换弹时长 + 段长 ≤ 换弹时长
等价于：    t ≤ 1 − 段长 / 换弹时长
```

#### 试过但失败的方案：裁短音频
把每段裁到 280ms 看似能塞进 1.0 秒，但**这批录音的重音在后段**——
"Mag In" 是「插入的咚」+「拍实到位的咔」两声，最响的那声在 0.3~0.4 秒。
裁到 280ms 后实测 `g36_reload_3_v1_magin` 从 **-3.8 dB 掉到 -15.9 dB**，
听起来变成一声闷响。**已回滚，音频保持完整。**

#### 现在的取值
`0.15 / 0.58 / 0.80`，配合「换弹 1.3 秒 + **两段**」是完美排开的：
```
0.195 ~ 0.625   拔弹匣
0.754 ~ 1.264   插弹匣     间隔 0.13s，尾部不溢出
```

#### ⚠️ 物理限制：1.0~1.3 秒放不下三声
1.41 秒的音频 + 开头抬手时间，要完整排开至少需要 **1.8 秒**。
所以两条路二选一：
- **A（推荐）**：`Reload Cues` 的 Size 改成 2，去掉拉枪机；换弹时长统一 1.3 秒
- **B**：保留三声，换弹时长加到 1.8 秒（动作会很慢）

如果哪天动画里确认有拉枪机动作、且愿意接受慢换弹，把时长调到 1.8 再把 Size 改回 3。

### 20:40 换弹逻辑结束点与动画结束点解耦（用户 20:34 反馈）

**问题**：`Rifle_Reload_2` 最后一段是「左手回到护木」的收势。收势时弹匣已经插好，
但逻辑仍算换弹中 —— 不能开火、声音还在响。之前 `PlayerReloadAnimator` 是
**逻辑进度 1:1 映射动画位置**（`Play(hash, progress)`），所以两个结束点被绑死了。

**改法**：引入 `Anim Done At`（默认 0.85），把两个时刻拆开。

```
逻辑 0 → 1.0            动画 0 → 0.85（弹匣插好，此刻可开火）
逻辑结束后 Recovery 0.3s  动画 0.85 → 1.0（左手回护木的收势继续演完）
```

实现要点：
- 换弹中：`Play(hash, progress × animDoneAt)`
- 逻辑结束后进 `Phase.Recovery`：手动把动画位置从**实际位置**推到 1.0（不是固定从 0.85 起，
  否则换弹被切枪打断时会跳帧）
- 收势期间权重保持满，播完再 `FadeOut` → 最后才 `SetBool(false)`
- 状态机里要按 `Phase` 分四段：Idle / Reloading / Recovery / FadingOut

**音频同步**：cue 的时间点语义变成「动画位置 ÷ 0.85」。
`ReloadTiming` 改成 拔弹匣 0.35（动画 30%）、插弹匣 0.82（动画 70%）、
拉枪机 1.05（动画 89% → 超出逻辑范围，`CollectReload` 会自动丢弃并在报告里说明）。

**副产品**：`bolt` 现在会被自动跳过，不用再手动改 `Reload Cues` 的 Size。
以后想要三声，把 `Reload Duration` 加到 1.8 并把 `ReloadTiming` 里 bolt 改成 0.98 重跑即可。

**调参位置**
```
Hierarchy → Player → Avatar → 模型根 → 检查器 `Player Reload Animator`
  · Anim Done At        0.85   （逻辑结束时动画播到哪）
  · Recovery Duration   0.3    （收势播多久）
```
`Anim Done At` 调大 → 更早能开枪、收势更短；调小 → 更晚能开枪、收势更完整。

### 21:10 命中反馈重做：COD 风格白色米字（原「扩散+米字」作废）

**旧实现的问题**：命中时是把**准星本身**往外撑开再收回 —— 没有独立图形、没有旋转、方向还是向外的。
看起来只是"准星变大了一下"，没有 hitmarker 的独立存在感。

**新实现**：米字是**独立绘制的 4 条线**，和准星分开画（准星只保留连射张开）。

```
时间轴（默认参数，整轮约 310ms）
0    ~ 30ms    渐显：alpha 0→1，位置停在外扩状态（gap 14px）
30   ~ 130ms   收缩：四条线向中心收到 gap 5px，EaseOutCubic（冲劲大、收尾稳）
130  ~ 210ms   保持：形状不动（连发时这一段会被无限延长）
210  ~ 310ms   淡出：alpha 1→0
```

**连发策略（关键）**：
- 当前**还有米字**时命中 → **绝不重启**，只把 `_hitKeepUntil` 推到此刻
- 因为 `HitmarkerTotal` 依赖 `_hitKeepUntil`，连发期间 total 一直被推后，
  `_hitAge` 永远追不上 → 米字稳定停在"收缩到位、alpha=1"
- 停火后 `_hitKeepUntil` 冻结 → 80ms 后开始淡出 → 133ms 完全消失
- 角度**整轮只随机一次**，不每发重摇（86ms 变一次角度会抖）

**`hitHoldTime` 必须大于连发间隔**：700 发/分 = 86ms，若停留为 0，
两发之间 alpha 会掉到 0.14（周期性变暗）。默认 0.08 覆盖到约 700 发/分。

**形状**：4 条线指向上/下/左/右，中心留空。`hitBaseAngle` 设 45 就变 X 形（COD 经典样子）。

**分辨率适配**：`hitScaleWithScreen`（默认开）按 `Screen.height/1080` 缩放米字，
封顶 1.8 倍。**只作用于米字，不动准星**（准星尺寸是手调过的，不能因换分辨率就变样）。

**位置**：画在准星位置（鼠标 + 后坐抖动），不是写死屏幕中心 ——
本项目准星跟随鼠标，写死中心会和准星分离。

### 9.1 武器槽文字重叠

**现象**：左栏武器槽里 `G36C(暂不可用) 槽里没有武器` 糊成一团（玩家截图）。

**根因**：`MenuUi.SetEnabled(按钮, false, 主题, 原因)` 会把按钮文字**覆盖**成「（暂不可用）+ 原因」（`MenuUi.cs:127-128`）。武器槽「卸下」按钮只有 60px 宽，塞进 11 个字必然溢出，撞上同行右侧的状态文字。

**方案（已定）**：`StashPage.RefreshWeapons` 里禁用卸下按钮时**不传 reason**：
```csharp
MenuUi.SetEnabled(view.Unequip, false, _t);   // 原：false, _t, "槽里没有武器"
```
状态行已有「空槽」提示，不丢信息。备选：按钮加宽到 90px 或文案缩短为「空槽」。

### 9.2 卸下后仓库里看不到新格子

**现象**：点「卸下」后枪的名册状态对了，但右侧仓库网格里**不出现**那把枪；必须拖动别的物品或再卸一把（触发 `RefreshAll`）才刷新出来。

**根因**：`StashPage.SaveWeaponChange` 只调 `RefreshWeapons()` —— 那个函数只刷新**武器槽小网格**（`_slotGrids`），**没刷新仓库大网格** `_stashGrid`（它只在 `RefreshAll` 里刷，而 RefreshAll 只在开页面/拖拽结束时跑）。

**方案（已定）**：`SaveWeaponChange` 里的 `RefreshWeapons()` 改成 `RefreshAll()`。
（`RefreshAll` 已包含武器槽 + 仓库 + 中栏，且拖拽中会自动跳过，安全。）
顺带：错误分支（卸下失败）保持 `RefreshWeapons()` 就行——那种情况容器没变。

### 9.3 G36C 与 M4 换位后，模型不换（HUD/伤害对，模型错）

**现象**：把 1 号位的 G36C 和 2 号的 M4 互换 → 进游戏 HUD 显示 M4、伤害也是 M4，但**手上模型还是 G36C**。默认配装（不换位）时一切正常。

**根因（两个叠加，都已查实）**：
1. **场景里有两个 `WeaponHolsterSystem`**：Player（fileID 1395625032）上那个的 `weapon`/`handSocket`/`backSocket` 全是 `{fileID: 0}`（**死的**，`RefreshGuns` 第一行 `if (!handSocket) return;` 直接退）；真正干活的是子物体上的 prefab 实例（1916472379，引用都配了）。而 `WeaponRosterBinder.RefreshWeaponPresentation` 用 `GetComponent<WeaponHolsterSystem>()`（同物体查找）→ **只找到死的那个** → 名册换模型后背枪系统从不刷新。
2. 真背枪系统在**子物体**上，`CollectGuns` 用同物体 `GetComponent<WeaponSlotBinding>()` → 永远 null → **静默回退「WeaponSocket 子物体顺序」**。默认配装的绑定顺序 [G36C, M4, GL] 碰巧和名册一致，所以互换之前一直没暴露。
