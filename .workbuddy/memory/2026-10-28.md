## 命中音效改为「dB 增益 + 峰值归一化」（用户反馈听不清）

**根因（两个叠加）**
1. 工程里**没有任何 AudioMixer 资产**，AudioService 四个组引用全是 `fileID: 0` → 所有声音直出 Master，
   之前"分总线"只是代码留了字段、资产没建，所以没有总线能单独调命中声。
2. `AudioSource.volume` 上限就是 **1.0（0dB）**，原字段 hitSoundVolume=0.7 已经把上限用掉大半，
   枪声接近满幅 → 提示音顶不过去，永远听不清。

**做法**：绕开 volume 上限 —— 把 clip 采样乘增益**重建一个内存 clip** 再播，dB 可以超过 0。
- `CrosshairHud.hitSoundVolume`（线性 0~1）**已删除**，换成 `hitSoundGainDb`（-30 ~ +12，默认 0，-30 = 静音）
- 新增 `hitSoundNormalize`（默认开）：峰值补到 -1 dBFS（上限 +26dB）。网上提示音常录得很轻（-20dBFS），
  不补的话加多少 dB 都压不过满幅枪声
- 削波检测：`peak*totalGain > 1` 时 Console 警告一次（提示剩余余量 + 建议降枪声），改参数后重新允许提示
- `GetGainClip()` 缓存重建结果（键 = clip + dB + normalize），参数不变不重复重建
- 重建失败（clip 非 DecompressOnLoad）退回原 clip 播放，不静音

**踩坑（差点编译报错）**：CrosshairHud 里原本已有 `OnDestroy`（清 _ring 贴图），我新加了一个清 _gainClip 的
→ 同文件两个 `OnDestroy` = CS0111 重复定义。已合并成一个。**教训：加生命周期方法前先 grep 一遍有没有。**

**相关位置（给用户降枪声用）**：`Assets/Audio/Config/WeaponAudio_G36C.asset` / `_M4A1.asset` → `Volume`（0.9）

## 霰弹枪 DP-12（替换 2 号位）+ 双管泵动机制

**用户拍板**：音效暂时静音 / 泵动用**程序动画** / 数值走**真实向** / 泵动**必须完成**（不能切枪换弹打断）/ 伤害飘字一次开火只弹**一个总数**。

**DP-12 真实机制（查证 Wikipedia）**：双管 + 双管式弹仓（各 7 发）+ 膛内 2 发 = 16；
**单扳机两发**（第一发右管、第二发左管），之后必须泵动（拉护木）把两发同时送进膛室。
所以节奏是「砰→砰→泵动→砰→砰」。

**逻辑层（WeaponSlotDefinition + WeaponController）**
- 新字段：`pelletsPerShot`(1) / `pelletSpreadDeg`(2.5) / `pumpAfterShots`(0) / `pumpDuration`(0.45) / `pumpKick`(0.06)

  飘字合并成一个总数；`ShotResolved` 每颗都广播 → 弹着特效每颗都留印，准星米字有 0.02 秒最小间隔所以只响一次）
- `SpreadDirection`：圆锥内随机，半径用 `sqrt(random)` 保证圆面均匀（否则弹丸都挤中心）
- 泵动：`AdvancePump()` 打满 `pumpAfterShots` 发后设 `_pumpTimer`；`IsPumping` 期间
  **禁止开火 / 切枪 / 换弹**（用户选"必须完成"）

`sin(PumpProgress01 * PI)` 让枪模沿 `Vector3.back` 后拉 `PumpKick` 并下压 —— 程序动画，不依赖动画资源

### 关键设计决策

**1. 不升 schemaVersion（决定性前提）**

- `ItemStack.InstanceId` 是 `long _nextId++` 的运行期句柄，`ItemStackDto` **故意不含它**

## 编译错误修复（CS7036 / IReadOnlyCollection.Contains）

`WeaponRoster.FromDto` 里对 `IReadOnlyCollection<string>` 直接 `.Contains(id)` — 该接口没有 `Contains` 实例方法，
文件又没 `using System.Linq`，编译器误解析到 `MemoryExtensions.Contains(ReadOnlySpan<char>, ReadOnlySpan<char>, StringComparison)`
→ CS7036 缺 comparisonType。修法：入口处转 `HashSet<string>(knownDefIds, StringComparer.Ordinal)` 再查，
既绕开解析歧义，也把「每条记录线性扫一遍」变成 O(1)。**教训：接口类型上不要直接调 .Contains，先转 HashSet。**

## 编译错误修复（CS0826 / hidden `new[]`）

`WeaponRosterTests.cs:406` 写 `dto.slotInstanceIds = new[] { null, null, null }` — 三个元素全是 null，
隐式类型数组推不出元素类型 → CS0826 + CS0029。改成 `new string[] { null, null, null }`。
**教训：`new[]` 里至少要有一个能定型字面量；全 null 必须显式写元素类型。**

**正确写法**：`modelPrefab: {fileID: <根GameObject ID>, guid: <prefab guid>, type: 3}`
（`type: 3` 表示 prefab 资产；fileID 必须是该 prefab 内 `--- !u!1 &<id>` 的根物体，`m_Father: {fileID: 0}` 那条 Transform 对应的 GameObject）
**验证方法**：场景里已有的 `projectilePrefab` 就指向 7936494813980292917，可与手写值对照。
**教训**：手写资产 YAML 的引用一律拿工程里**已有正确引用**当模板，别自己编 fileID。
**补充**：`m_SourcePrefab: {fileID: 100100000, ...}` 在场景里是合法的 —— 那个字段类型是 `Prefab`（不是 `GameObject`），
所以 100100000 能用；把同一写法抄到 `GameObject` 字段就报 mismatch。**字段类型不同，fileID 的含义也不同。**

**判断"警告是否已修"不能只看 Console**：Unity 不清历史日志。看**时间戳**与文件 mtime 的先后，
或用一个"如果没修就会失败"的工具反证（例：㊵ 按 `def.modelPrefab == 场景枪的 prefab 源` 配对，
引用为 null 时必然报"找不到定义"，它报"全部一致"即证明引用已生效）。
