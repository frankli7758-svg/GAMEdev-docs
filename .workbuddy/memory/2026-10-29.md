## 阶段 5 一测就炸：换枪后手握空气 / 模型全在背后 / 腿上卡枪（14:45-14:52）

**现象**（玩家实测）：替换后枪位置错；切任何号位手里都是空气；几把模型一直留在背后；腿上卡着一把 G36C，且**不管拿几号都是它在开枪**。空手进局正常。

**根因（我自己埋的）**：为了处理"同型号第二把只有一个枪模"，我在 `WeaponRosterBinder.AssignModelForSlot` 里把**另一个槽的绑定清成 null**，同时允许两槽指向同一 Transform。
1. "启用中但没有模型"的槽让 `WeaponSlotBinding` 看起来不完整 → `WeaponHolsterSystem.CollectGuns` 走 `BindingCoversEnabledSlots` 失败分支，**回退"WeaponSocket 子物体顺序"**；
2. 但运行时枪早被搬到手上/背后，子物体顺序≠槽位顺序 → `_guns` 可能是 0 个元素 → `ApplyLayout` 直接 return → **整套背枪系统冻结**：手上的枪被上一步摆到背后就再也不回来（手握空气）、被解绑的模型停在切枪动画半途（腿上的 G36C）、枪口特效跟着它（永远是它在开枪）。

**修法（4 处，核心原则：绑定表绝不能出现空洞）**：
1. `AssignModelForSlot`：**绝不清别的槽的绑定**；同型号允许共用同一枪模，只警告。
2. `FindModelForDef(def, forSlot)`：按槽找**没被别的槽占用**的模型，实在没有才共用（+`IsSameWeaponModel`/`IsBoundToOtherSlot`）。
3. `ClearModelForSlot`：模型还被别的槽用着时不隐藏。
4. `WeaponHolsterSystem`：`BindingCoversEnabledSlots` → `BindingHasModels`（有任何一个模型就以绑定表为准，子物体顺序只给"完全没配过绑定"的老场景）；`ApplyLayout` 改成**手上那把先落位**、再摆背后，同一枪模只摆一次（`PlacedAtEarlierUsableSlot`/`UsedByUsableSlot`）。

**教训**：表现组件的绑定表是唯一真源。任何"临时解绑"都会让下游退回一条**已经不成立**的旧路径。要表达"这里就是没有"，必须用显式状态，不能靠清空。

## 换枪显示修复第二轮：野模型 + 同型号只有一份枪模（14:56-15:01）

**现象**：装备两把 G36C，模型显示的却是 M4；身上三把枪只看到两把（手上一把、背上一把，一个背位空着）。

**两个根因**：
1. **野模型**：`AssignModelForSlot` 换模型时只覆盖 `weaponModels[slot]`，**从不处理被换下来的旧模型**。旧模型从此不在任何槽的绑定里，背枪系统再也不会摆它 → 停在原地一直可见（原来是 M4 就永远显示 M4）。
2. **同型号共用一个枪模**：场景每型号只有一个模型，三把枪物理上只有 2 个物体 → 必然一个背位空着。

**修法**：
1. `AssignModelForSlot` 记住 `previous`，换完后若它不再被任何槽引用 → `SetActive(false)`。
2. 新增 `WeaponHolsterSystem.DuplicateModel(source)`：用**场景里那份模型**复制（缩放/朝向/子挂点 FirePoint·GripPoint·LeftGrip 全原样，不碰 prefab、不重排 WeaponSocket），复制体登记同一份手上姿态。模型被别的槽占用时先复制再绑；复制失败才退回共用并警告。
3. `Bind()` 开头新增 `WarmupHandPoses()`：让背枪系统在模型还挂在 WeaponSocket 下时先采集手上姿态，否则复制模型时拿不到基准。

**边界**：复制体是运行时物体，退出 Play 就没了（每次进局按配装重建）；空出来的复制体会被隐藏+解绑，下次同型号优先复用，不会无限增长。

**教训**：换绑任何"数组里的引用"时，**必须处理旧值**。旧值没人管就会变成幽灵留在世界上——和之前"清空绑定"是同一类错误的两个方向（一个是状态残缺，一个是对象散落）。
