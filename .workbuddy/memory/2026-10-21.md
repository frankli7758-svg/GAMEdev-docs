## 06:45 修正：玩家存入的物品必须保持「已发现」（用户实测反馈）

**用户报**：把自己已经认识的 CPU 拖进容器后，它变成灰色、还要重新搜一遍。
原话：「这个物品应该依旧是一颗 CPU，且是已搜索状态，不会变成灰色需要搜索」。

**根因**：`SyncEntries()` 对所有新条目一律 `Revealed = false`。
它只区分了「新出现的物品」，没区分**是谁弄进来的** ——
战利品是玩家没见过的（要搜），玩家手上的东西他当然认识。

**修法（三处）**：
1. `SyncEntries(bool newEntriesRevealed = false)`：生成路径 false，玩家操作路径 true
2. **新增 `ContainerInstance.TryStoreFrom(source, uid, out reason)`**（转移进 + 自动已发现）
   与 **`TryTakeTo(target, uid, out reason)`**（转移出 + 标取走 + **未发现直接拒绝**）
   → 作为**唯一搬运入口**，UI 不要自己 `TryTransferTo` + 手动同步
3. `LootableContainer.RefreshAfterContentChanged(bool)` 降级为兜底重对齐，注释写明别当搬运 API

**为什么不会泄露容器原有未知物品**：跨容器转移走 `TryAutoPlace`、**不合并**，
玩家存入的永远是独立条目，「已发现」可以单独给。
⚠️ 将来若做"快速存入"改用 `TryAdd` 就会合并，那时必须重新考虑（已写进注释）。

**顺带补的规则**：未搜出来的物品不能拿走（`TryTakeTo` 拒绝并给原因），
否则 UI 列个"全部物品"就能绕过搜索白拿。

**验证**：EditMode **95 / 95 通过**（新 5 条：存入即已发现 / 不泄露原有未知 / 未发现不可拿 / 已发现拿走不影响其他条目 / 存回再拿走）

**教训（要长期记住）**：
状态由**多条路径共同维护** = bug 温床。这次不是逻辑写错，而是**入口太多** ——
谁都能调 `SyncEntries()`，于是"该传 true 的那次"被漏掉了。
收敛成两个语义明确的方法后，调用方不需要知道"要不要标记已发现"，也就忘不了。
**以后凡是"某状态由调用方传参决定"的设计，都要问一句：能不能把它收敛成一个不会传错的方法。**

## 09:25 容器-4 前置审查：EventSystem / Cancel 的配置冲突清单

### 已确认的客观事实（实测，不是推测）

| 项 | 值 | 含义 |
|---|---|---|
| `com.unity.inputsystem` | 1.20.0 | — |
| `activeInputHandler` | **1** | **仅新输入系统**（旧 Input Manager 已禁用） |
| 场景 EventSystem / Canvas | **0 / 0** | 完全干净，没有既有冲突 |
| 代码里 uGUI 引用 | **0** | 没人在用 `UnityEngine.UI` |
| `Assets/InputSystem_Actions.inputactions` | 存在（Unity 6 模板自带） | **孤儿资产**：代码从未引用，GameInput 是纯代码动态建 action |

**推论 1（决定实现）**：`activeInputHandler = 1`，所以 EventSystem 的输入模块**必须是 `InputSystemUIInputModule`**。
如果用 `StandaloneInputModule`（旧版），运行时会抛
`InvalidOperationException: You are trying to read Input using the UnityEngine.Input class, but you have switched active Input handling to Input System package`。

**推论 2**：`InputSystem_Actions.inputactions` 如果被设为 Project-wide Actions，它的 Player map（WASD / 空格跳 / 左键攻击）会与 GameInput 并存 → 出现"按空格没反应但事件被吃掉"这类怪事。**必须保持 Project-wide Actions = None。**

### 发现三个真冲突（都在现有代码里）

**① 光标争夺（最可能被用户直接看到）**
- `CrosshairHud.OnEnable` → `Cursor.visible = false`
- `CrosshairHud.OnDisable/OnDestroy` → `Cursor.visible = true`
- `DebugPanel.SetOpen` → `Cursor.visible = open || crosshair == null`
- 库存界面要 `Cursor.visible = true`
- **后果**：谁最后写谁赢。可能出现"库存开着但鼠标不见了"，或者"关了库存光标还在"。
- **修法**：引入单一光标仲裁（一个 `CursorArbiter` 静态类，按"有无模态 UI"决定），三个地方都改为通过它申请/释放。

**② 输入屏蔽互相覆盖**
- `DebugPanel.SetOpen(false)` → `_moveInput.inputEnabled = !open && alive`（无条件写回 true）
- 库存界面的「搜索中禁止移动」也写 `inputEnabled`
- **后果**：F1 面板一开一关，会把"搜索中禁止移动"错误地恢复成可移动 → 玩家能一边搜箱一边跑。
- **修法**：把 `inputEnabled` 改为引用计数 / 或用统一的 `InteractionMode` 单一状态源（Normal / BackpackOnly / Searching），各组件只读不算。

**③ Esc 双职责**
- `GameInput.StartRebind` 用 `WithCancelingThrough("<Keyboard>/escape")`
- 新增 `GameInput.Cancel`（Esc）后，改键时按 Esc 会**同时**取消改键 + 关闭库存界面。
- **修法**：改键期间置一个 `IsRebinding` 标记，Cancel 在 `IsRebinding` 时不消费。

### ① 只出现一个「主」字、物品块全不可见 —— 真 bug，本轮最有价值

**根因**：`UiFactory.Inset()` 对**点锚点**（anchorMin == anchorMax）用了
```csharp
rt.offsetMin = new Vector2(inset, inset);
rt.offsetMax = new Vector2(-inset, -inset);
```
点锚点下 offset 与 sizeDelta 是同一组自由度的两种写法 → `sizeDelta = offsetMax - offsetMin = (-2i, -2i)`
→ 物品块变 **-3×-3 → 整个节点不渲染**。
而子节点里的 TMP 文字按自身文本边界绘制、**不受父节点负尺寸约束** → 只剩一个字浮在格子上。

**修法**：`Inset` 分两种锚点 —— 拉伸锚点走 offset；点锚点 `sizeDelta -= 2i` + `anchoredPosition += i*(1-2*pivot)`。

**记进速查卡坑 #26**。口诀：**点锚点下 offset 不是"内缩"，是"换算"**。

## 11:35 容器-4 第二轮实机反馈：5 项修正（斜纹未知块 / 放大镜 / R 键 / 弹药 HUD）

用户给了两张参考截图（塔科夫式斜纹格子 + 放大镜居中）。5 件事：

### ① 未知物品看不清 → `UnknownCellGraphic`（自绘）
原来纯色 `(0.20,0.21,0.25)` 跟格子背景亮度差太小。
新建 `Gameplay/Inventory/UnknownCellGraphic.cs`：
- 填充 `(0.028,0.031,0.040)` **比格子背景更暗** → "凹进去"的观感
- 45° 斜纹：线族 `u - v = c`，间距 7.5px / 粗 1.6px / 白 5.2%
- 1px 边框，白 17%
- **斜纹裁剪算法**：每条 c 的可见段被 `[0,w]` 与 `[c,c+h]` 夹住，取交集 → 不需要 `RectMask2D`、不需要子节点

### ② 放大镜"转的位置不对" —— 真 bug
`SearchLens` 用 `localRotation`，**旋转永远绕 pivot**。原来 `_lens.pivot = (0,1)`（左上角）
→ 放大镜是绕格子左上角"甩"，不是自转。
修：`pivot = (0.5,0.5)`，定位改成直接给"物品矩形中心点"（pivot 在中心时 anchoredPosition 就是中心偏移）。

### ③ 放大镜将来是贴图 → 留 `lensSprite`
`InventoryGridView` 新增 Inspector 字段：
`lensSprite`（留空=自绘圆环；拖 png 进来就自动变贴图，代码不改）、`lensScale`、`lensColor`、
`unknownFill`、`unknownHatchSpacing`。

### ④ R 键"有时没反应" —— 两个原因
1. **鼠标不动时 `OnDrag` 根本不触发** → 停下后按 R 没人调 `UpdateDrag`
2. **同帧被调用两次**（`InventoryUi.Update` 和 `ItemCellView.OnDrag`）→ 一次按 R 翻两次 = 没转

修：`Update()` 每帧用 `_lastDragScreenPos` 主动刷一次 + R 用 `_lastRotateFrame` **同帧去重** + 旋转打日志。

### ⑤ 界面打开时隐藏弹药 HUD
`AmmoHud.OnGUI` 开头 `if (InteractionMode.AnyOpen) return;`
走统一状态源，不自己判断"有没有 UI"。
