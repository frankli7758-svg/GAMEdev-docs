### 测试抓到的真 bug（已修，重点记）

`TryAdd` 对不可堆叠物品按「剩余数量」切块 → `TryAdd(Cpu, 3)` 生成一条 `count=3`，
**违反「两把属性相同的 AK47 不能堆叠」铁律**。
修复：① 不可堆叠时 `chunk = 1` 逐条创建 ② `ItemStack.Create` 用 `maxCount = StackLimit > 1 ? StackLimit : 1`。

> UI 上看不出来（玩家只看到"3 个 CPU"），只有数条目才暴露 —— 这就是写单测的理由。

### 设计落地对照

| 设计要求 | 实现 |
|---|---|
| 不能有第二份占用表 | 占用永远 `GetOccupant` 现算，**无缓存数组** |
| 包围盒 + mask | `bool[] _mask`，null = 全可用 |
| 旋转宽高只在一处交换 | 只有 `ItemDef.FootprintX/Y`，其它地方禁止手写 |
| 原地移动不被自己挡 | `CanPlaceAt(..., long ignoreInstanceId, ...)` |
| 拆分原子 | 先放新条目成功才扣数量 |
| 跨容器原子 | 先放目标成功才从源删 |
| 生成确定性 | `CombineSeed` 自己算哈希，**不用 `string.GetHashCode`** |
| 0.01% 可验证 | 概率测试跑 10 万次统计 |
