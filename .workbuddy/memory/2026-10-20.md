## 09:15 修「追击中突然丢目标」的真正根因（用户提供实测数据）

**用户给的数据（关键）**：
```

```

**我的计算**：
- 距离 = sqrt(7.71² + 11.99²) = **14.25 米** → 在 25 米内 ✅
- 目标方向 = atan2(7.71, -11.99) = **+147.3°**；朝向 -60.7° → **差 152°**
- 152° > 60°（120° 视野的半角）→ `seesTarget=false` **是真的**

**但这不是朝向 bug，是设计缺陷**：**120° 扇形被拿去"维持追踪"，而不只是"发现"**。
玩家被僵尸发现之后绕到侧面，就莫名其妙被忘了 —— 这不符合直觉。商业游戏普遍做法是"进入战斗态后视野宽容"。

**三个修复**：
1. **`CanSeeTarget(targetPos, distance, ignoreFieldOfView)`**：新增第三参数。
   `Alert` / `Chase` / `Attack` 时传 `true` → **只查距离 + 遮挡，不查扇形**。
   `Idle` / `Search` 时传 `false` → 必须进扇形（**背后偷袭仍然有效**）。
2. **`UpdateFacing` 移动中的朝向优先级**改为：看见目标 > 有明确去向（Chase/Search 的目标点）> 路径切线。
   原来只朝切线，玩家在侧面时扇形永远扫不到，形成"看不见→不转头→更看不见"死锁。
3. **修搜索点缓存失效**（蓝点出现在错误位置的真因）：
   - 原来 `ResolveSearchPoint` 只比 `_cachedSearchStep == _brain.SearchStep`
   - `SearchStep == 0` 时，`HearNoise` 更新了 `LastKnown`，步数没变 → **缓存不失效** → 僵尸走向好几秒前的旧点
   - 现在额外校验锚点：`|LastKnown - cachedAnchor| < 0.5 米` 才算缓存有效（加 `_cachedAnchorX/Z/Valid`）
   - 这解释了"当前搜索点 = (0,-5.4)"而玩家在 (18,-23) 的现象 —— 那是旧缓存点

- 未被发现 → 必须进扇形（背后偷袭有效）
- 已经交战 → 只要没跑出 25 米、没被墙挡，就一直锁着你
- 遮挡与距离仍然生效，所以"跑进掩体躲好"依然能甩掉

### 8 个预留点（写进 `Docs/阶段7-设计说明.md` §3.7，并成为 7.1 验收项）

1. 条目存 `GridX / GridY` —— 放置结果进数据，不是 UI 临时算
2. `TryAutoPlace()`（first-fit 找位）与 `TryPlaceAt()`（指定坐标）**必须是两个函数**，前者内部调后者
3. **`CanPlaceAt()` 纯查询**：只回答"放得下吗"，不改任何数据 → 将来拖拽的半透明预览靠它
4. `InstanceId` **全局唯一**（不是容器内序号）→ 跨容器搬运（背包→仓库）不撞 id
5. 条目存 `Rotated` 布尔
6. 占位尺寸**只走 `GetFootprint(def, rotated)` 一个函数**，禁止任何地方手写宽高交换（漏一处就错位）
7. `Remove(uid)` **返回完整 `ItemStack`**（含 uid / 数量 / 旋转态）→ 跨容器拖拽是"拿走再放下"
8. `TrySplit(uid, count, out newUid)` **本期实现核心逻辑，但不给 UI 入口**

### 为什么拆分核心逻辑要本期就写

拆分 = "从条目 A 拿走 n 个、生成条目 B"，它是**拾取 / 丢弃 / 合并的公共底层**，不写就要在别处重复实现数量搬运。
且本期就可能撞上：容器里一条 500 张钞票，背包放不下全部。
**函数先有、菜单后加** 最省。

### 拆分约束（提前定死）

- 只能拆 `stackLimit > 1` 的条目（`= 1` 的东西只有一个，拆不出来）
- `0 < count < 当前数量`（拆全部 / 拆 0 都走别的操作）
- **失败必须整体回滚**，不允许"数量已减、新条目没生成"的半拆
- 拆分不改变价值总和（500×100 = 200×100 + 300×100）

### 另一条定死的：`InstanceId` **不进存档**

它只是运行期句柄（给 UI / 拖拽指代"哪一条"），读档时重新分配。
存档只存「容器 → 条目 → `物品id / 数量 / GridX / GridY / Rotated`」。存档干净、可读、可手改，也不会因 uid 规则变化而迁移。

**背包网格尺寸决定"旋转"有没有意义** —— 若背包只有 2 列，太阳能板旋转成 4×2 永远放不下，功能等于白做。
