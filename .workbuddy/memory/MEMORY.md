## 核心设计支柱（2026-10-19 用户明确，长期有效）
- **局内时间系统是这个游戏的差异点**：白天怪弱且少、可安全搜外围；黄昏压力上来；黑夜怪强且多、视野受限，需要思路与操作；**玩家不必熬到黑夜，可以在天黑前火速撤离**。
- 设计意图：把"搜多少"和"什么时候走"变成同一个决策，制造风险与收益的取舍。
- 实现铁律：时间属于规则层（`RaidClockRules`，固定 tick），**禁止用 Time.time 直接驱动数值**；光照与 UI 只在表现层跟随。
- 详见 `Docs\项目速查卡.md` §3.2（含三段结构与待拍板参数）。
- **撤离分级（已定）**：白天～黄昏用普通外围撤离点（走到即走）；**黑夜外围撤离点失效**，必须用**信号枪召唤直升机**，需原地驻留等待，且信号枪亮光与直升机噪音会**吸引敌人**，撤离点变成战场。
- 未定：一局总时长、是否能"主动等待"天黑（暂未想到理由）、白天僵尸分布（倾向：外围 0 + 核心区少量 + 室内若干）。
- 该设计会引入新系统：撤离点、信号枪、直升机状态机、**僵尸听觉（噪音事件）**——现有僵尸是"无限感知"，需要升级。
- **夜间直升机撤离（COD20 式，已定）**：信号枪 → 30s 到达 → 驻留 30s（到点强制飞离，不管玩家在不在）→ 玩家登机后加速为 5s 成功撤离；错过需等下一班（驾驶员怕尸潮，不会无限待命）。
- **昼夜系统的原始目的**：最初设想是第三人称 PVPVE——白天同阵营不可攻击，**天黑后身份识别失效 → 玩家可互相攻击并掠夺物资**。当前单机不做 PVP，但保留为世界观与未来联机基础。
- **AI 需求（阶段 6 起）**：NavMesh 寻路（包已装）、多源噪音（走路/冲刺/开枪/碎玻璃）、环境交互物（玻璃、撬锁铁门，有奖但有响）。
- **第二模式：堡垒守塔（无尽尸潮）** —— 资源无限、放松割草；与搜打撤互补（带出物资→堡垒变强；守塔技能点→搜打撤收益）。属于"第二个游戏"，排期在阶段 9 之后；两者共用 Core，只换资源/生成/场景配置。
- **存档硬要求**：阶段 7 必须按模块 + schemaVersion 设计（profile/stash/skills/fort），否则双模式必然返工。
- **区分"已定/设想"**：文档 §3.3 顶部有状态图例（✅已定 / 🟡待定 / 💭设想）。技能树、靶场、制作台、商人、堡垒扩建都属 💭 设想，**不要当需求做**；确定的是"两个玩法必须互通，不能各玩各的"。
- **堡垒 = 真实 3D 地图（💭）**：玩家登录后在堡垒内自由活动，设施可走过去交互，**也可用按钮直接跳转**（沉浸但不累）。
- **进场/撤离演出（💭）**：参考绝地潜兵 2——钻进降落舱从天而降、舱门打开开始行动；撤离走滑索上直升机 + 回营地动画，背景模糊展示收益。不是固定加载画面。
- **地基原则（用户核心要求）**：先打好地基，之后只加内容（新枪/新地图/新角色），不重做底层。做法是"留缝"：转场 `ITransition`、流程 `GameFlow`、交互 `IInteractable`、数值配置化、存档分模块。**反过度设计铁律**：只有单一实现的抽象只写接口、不造框架。详见 §3.5。

## 沟通偏好（用户明确要求）
- **给 UI 操作步骤时一律写中英双语**（Unity 汉化不完整，同一界面里中英文混杂，用户需要对照）。例：「新建（New）/ 立方体（Cube）/ 层级（Hierarchy）/ 检查器（Inspector）/ 播放（Play）」。
- 用户是初学者：步骤要具体到点哪里、填什么数值、预期看到什么。
- **允许并鼓励主动提出更简洁的方案**（2026-10-22 用户原话）："今后如果发现比既定方案更简洁、稳定且不损失必要功能的实现方式，也可以主动提出，不必机械遵守之前的设计。" → 发现过度设计要当场说，不要照抄既定方案。
- **每个可调参数必须说明「层级路径 + 检查器组件名 + 字段名」**（2026-10-27 用户明确要求："请每次都告诉我是哪个层级还是哪个检查器"）：
  合格写法：「模型根 `HumanCharacterDummy_M` → 检查器 `Player Locomotion Animator` → `Fire Damp Time`」；
  不合格：「在 Inspector 里调」或「在 Player 上」。用户需要一次就能找到，不要让他翻组件列表。
- **准星永远不用红色**（2026-10-27 用户两次强调）：禁止状态靠形态区分（圆环+斜杠），不靠颜色。`CrosshairHud.blockedColor` 字段已删除，不要加回任何红色分支。
